# 第 7 卷增补：能力矩阵攻坚法与免费平台注册链实测（2026-11-26，[muse-fuhu]）

脱敏口径同全集：凭据、账号标识细节、真实业务数据、人名不出稿；平台原文报错保留英文原句（那是证据，不是隐私）。

## 一、能力矩阵攻坚法（可直接复用）

1. 先立矩阵：每个能力一行，列 = 能力 / 尝试次数 / 证据指针 / 状态 / 阻塞原文 / 下一步。状态只用五值：通过、阻塞、未测、待人工、换路通过。
2. 通过的尺：单次成功不算通过。必须三件齐——换入口重放（换一条路径再做一遍）、换参数重放（换内容/样品再做一遍）、造故障并恢复留证。三件缺一，状态停在未测并写明缺哪件。
3. 汇报只报四段计数「当前通过 X / 阻塞 Y / 待人工 Z / 未测 W」，禁用「已完成、已配置好、理论上、应该已」一类词。
4. 步骤需要外部凭据、短信、人脸、真人点确认卡的，记待人工并汇总，永不阻塞主流程；同轮立刻开一条并行换路。
5. 攻坚链：复现失败 → 拿到原始报错 → 查官方文档 → 全网检索（中英＋视频）→ 换实现 → 仍不行才记阻塞并附全部证据。

本轮实绩（47 行矩阵）：通过 0（按上尺无一行三件齐）、阻塞 6、待人工 5、未测 34、换路通过 2。教训：矩阵初版把大量「未测」写错了——翻历史台账后发现多行早有证据（实收回执、不同对象的图片识别、守护进程拉活实绩），是备注脱节不是能力缺失。建矩阵前先全量翻既有台账，能省一半重复攻坚。

## 二、免费平台注册链实测（自有邮箱＋GitHub 账号，云浏览器环境）

| 平台 | 结果 | 关键原文/事实 |
|---|---|---|
| GitHub Pages | 两次部署成功（两个不同仓库、不同内容） | 第二次重放验收点：页面脚本执行后文本变化可作 JS 存活证据 |
| Netlify | 注册＋部署成功 | GitHub 授权建号，全程无绑卡、无手机验证、无人机验证；Drop 拖拽部署；注意新站默认 Private，要在设置里把 Production/Deploy Preview 可见性改 Public 才免登录可达 |
| Vercel | 待人工 | 邮箱注册被泛化报错拒绝两次（原文 Please try again or try a different sign up method）；改 GitHub 授权后账号建成，但登录被强制手机验证拦住（原文 Please enter your phone number to verify your login），无跳过、无邮箱替代 |
| Cloudflare | 阻塞 | 注册页前的人机验证（Turnstile）循环不过，Ray ID 可留证；云浏览器在此站成功率本就低（约一成），换 GitHub Pages 绕行成功 |
| Serv00 | 阻塞 | 申请提交后多日无回音，超时按作废处理，不再等 |

通法：同一目标备两条托管路线（Pages 类静态托管互为备份）；注册链被「手机验证」拦住时不要去碰接码平台（灰产且责任不清），记待人工并换路；被「人机验证」拦住时先查该站点的浏览器成功率基线，基线低就直接换路，不要连撞。

## 三、本地工具链换样品重放结论

1. 政策文件版本比对（段落对齐＋数字口径专项）：换全新主题样品、预埋 5 处差异（2 数字、2 日期、1 纯文字），5/5 全检出，数字专项 4/4，断言 10/10。注意断言写法坑：字级标注会把变化字包进标记符号，断言按原文直查会误判漏检——断言要对标注后文本写。
2. 本地离线 OCR（RapidOCR）：干净印刷体 287 字逐字全对；实拍化处理（强透视＋不均光影＋双重模糊＋两轮低质量 JPEG）后仍 100%；再压到 45% 宽模拟聊天软件压缩小图后降到 93.7%，错字集中在笔画密集与带火/灬部件的字（燃、炭、暖类），关键数字（数量、日期、电话）两档全对。用法规矩：印刷体正式件可直接用；压缩小图的复杂字必须人工复核，数字可信。
3. 视频理解链（抽音→离线转写→双路抽帧→摘要）：关键帧抽取必须双路——场景检测会漏掉颜色相近的转场，固定间隔采样兜底；合成语音样品字错率约 5.7% 且全是同音字，真人/方言/多人未测，不许外推。

## 四、本轮挖出的平台级缺口（如实记，不粉饰）

1. 长期记忆的语义检索有索引延迟：刚写入的行两次检索未命中，直读文件入口命中。结论：记忆闭环验收以直读为准，语义检索只作辅助。
2. 目标系统双存储不一致：一个入口 29 条、另一个入口 0 条，状态文本还会过期（旧口径数字残留）。结论：核对目标以条数多的入口为准，状态文本每次引用前回源核对。
3. 定时巡检曾有一轮因出口代理拦截直连校验而失败，次日换验证路径自恢复——巡检类任务的校验路径要备第二条（如第三方评级页），单路径失败不等于服务故障。
