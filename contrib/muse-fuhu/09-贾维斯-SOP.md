# 第九章 SOP：贾维斯——从学到造（S0–S10 施工手册）

> 本章是操作手册。只读本章即可按 S0→S10 顺序把「常驻可唤醒、能听会说、大脑走云端、能调白名单工具、多终端打通」的语音助手一步步搭出来并逐项验收。凡写「写死」处不许自行改动；凡「强制停点」处，未经审核确认不许越过。

---

## 1. 本章目标与适用范围

- 目标：把已有底子（微信桥、米家连接、日历、记忆体系、云端语音试验台）升级为多终端贾维斯成品。能力全集 8 类：①常驻唤醒 ②语音识别 ③大脑 ④语音合成与克隆音色 ⑤工具调用/控电脑 ⑥长期记忆 ⑦智能家居与手机联动 ⑧HUD 界面。推进顺序写死：**先语音入口，再工具，再记忆**；界面最虚，⑤⑥才是真本事，不许先做 HUD 充数。
- 架构写死（混合路线）：**本地只做唤醒、ASR、TTS；大脑走云端**。不采纳本地全量大模型部署。
- 成品通过线（缺一不算完）：
1. Mac 中枢守护进程无人值守运行 ≥24 小时无崩溃、无需人工干预（看门狗日志为证）；
2. 全链（唤醒→ASR→大脑→工具→TTS）在 Mac 端到端跑通 S10 的 10 个规定场景，每场留完整日志与音频证据；
3. 两台音箱（不刷机路线）各 ≥10 次端到端问答，成功率与延迟有实测数据；
4. 电视 HUD 四态（待机/聆听/思考/播报）实拍照片齐全；
5. 微信接入点半链跑通（语音文件→文本、文本→语音文件），接口桩留好；
6. 第 5 节异常分支逐条演练并留记录，不许只写「已处理」。

| 小米音箱 A（Xiaomi Sound 类） | 语音入口＋播报 | 不刷机路线（S7） |

### 证据总规范（每步适用）

- 证据根目录：Mac `~/Documents/jarvis-build-evidence/`，每步一个子目录（`S0/`…`S10/`）。
- 日志统一 JSONL，每行含字段：`ts、step、event、latency_ms、ok`。
- **每步完成先发该步回报与证据清单，过关后再进下一步；不许攒到最后一次性报。** 回报格式见第 7 节。

## 3. 操作步骤（S0–S10，逐步施工、逐步验收）

### S0 环境基线
- 做什么：Mac 系统/芯片/内存/磁盘盘点；麦克风与扬声器设备清单；Python 与 sherpa-onnx arm64 可用性验证；模型下载校验（官方源，文件名逐一对齐下列清单）。
- 模型清单（写死，云端试验台已验证的同一组）：
- KWS：`sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20`（中英双语，3M 参数；tar 约 32MB）
- ASR：`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`（SenseVoice int8；model.int8.onnx 约 229MB）
- TTS：`kokoro-int8-multi-lang-v1_1`（Kokoro int8 多语，103 说话人；model.int8.onnx 约 109MB＋voices.bin 约 52MB）；默认中文男声 **sid=58**
- 三件套目录总占用约 802MB（含 tar 包）。
- 证据：`S0/env-report.md`（盘点表＋版本输出原文＋模型文件大小清单）。
- **通过线：三件套在 Mac 上各自单跑一次成功**（KWS/ASR/TTS 各留一条运行日志）。云端试验台参考基线（Mac 须重测，不许直接引用充数）：ASR 回转写 CER=0.000、KWS 阈值 0.25 一次命中、TTS RTF≈2.8（弱云 CPU）。
- 已实测参考（2026-11-25，Mac 侧 S0 已过）：sherpa-onnx 2.0.3；RTF 实测 ASR 0.053、TTS 1.164、KWS 0.026。

### S0.5 参考实现冒烟实测与路线决策 ——
- 做什么：装 isair/jarvis 官方打包版（macOS arm64），半天上限，实测四项：①唤醒响应 ②中文识别 ③中文播报（Piper）④句中喊名字接话；记录其大脑接 OpenAI 兼容后端的配置形态。
- 产出：`S0.5/smoke-test.md`（四项逐项结果＋录屏或日志）＋**路线决策书**：fork 改造 / 借鉴架构自研，二选一并写明理由（中文效果、许可、可控性、与 S3 协议衔接成本）。
- 决策参考（已核实事实）：该项目五层架构 listening/reply/memory/tools/output 可借鉴（快慢模型分层、滚动转写＋意图判定、回声检测、记忆三件套＋recall_gate＋存前脱敏、MCP 工具层均可拿来）；**边界写死**：自定义许可只许非商用、衍生须同许可、商用须另获授权；中文效果未验证；无多终端概念；**其听写功能在 macOS 26+ 不可用**（pynput 兼容问题），我方 Mac 正是 macOS 26.x，整仓替代前必须先过本停点。
- **通过线：决策经审核确认才许进 S1**；选 fork 时先交许可合规说明（非商用、保留 LICENSE 与署名）。

### S1 常驻唤醒
- 做什么：守护进程常驻监听，唤醒词「贾维斯」；滚动转写缓冲保留最近 30 秒；意图判定区分「喊它」与「提到它」；回声抑制——本机播报期间麦克风输入做回声门控，不许自问自答。
- 关键词文件生成（云端实测法）：用官方 `sherpa-onnx-cli text2token`（tokens-type 选 phone+ppinyin）生成，格式如 `j iǎ w éi s ī @贾维斯`；KWS 配置参考：keywords_score=1.0、默认阈值 **0.25** 起步，音频按 0.1s 分片流式喂入。
- 证据：`S1/wake-log.jsonl` 覆盖四组：①安静环境 20 次唤醒命中数；②电视外放/音乐背景下 10 次；③2 小时无人说话的误唤醒次数；④唤醒到开始聆听的延迟分布。
- **通过线：安静命中 ≥19/20；2 小时误唤醒 ≤1；延迟 P95 ≤800ms。**

### S2 语音识别（ASR）
- 做什么：SenseVoice int8 接入守护进程，流式分片喂入；配置 `language=zh、use_itn=True`。固定中文测试集 20 句（须含本项目词汇：茶园、办文、日程、米家设备名等，拟稿后经审核冻结，不许临测改集）。
- 证据：`S2/asr-test.md`：逐句原文/转写对照、CER 计算、Mac 上 RTF 实测、近讲（0.5m）与远场（3m）各一组。
- **通过线：近讲 CER ≤2%；远场 CER ≤8%；RTF ≤0.5（Mac 本地）。** 达不到就如实报数＋提改进方案，不许调测试集造数。

### S3 大脑接入协议（Mac 侧＋模拟器） ——
- 做什么：按下列契约实现 Mac 侧客户端与本地模拟器（模拟器返回固定回复，用于云端消费端就绪前独立验收 S4–S10）。**契约字段写死，不许自改：**
- 请求：`{req_id, ts, source: mac|speaker_a|speaker_b|wechat, text, context_ref}`（context_ref 只放滚动转写与记忆摘要的引用 id，不塞全文）
- 响应：`{req_id, text, actions: [{tool, args}], speak_target}`
- 快慢分层：本地先做意图分类（闲聊/工具/敏感拒绝），工具类与复杂问题才上云；敏感类本地直接按第 6 节拒绝。
- 证据：`S3/protocol.md`（契约＋时序图）＋模拟器往返日志 10 条（含超时与重试各 1 条人为注入）。
- **通过线：往返延迟（本地模拟）P95 ≤300ms；超时 8 秒触发兜底话术且不阻塞聆听。协议经审核确认才许往下走。**

### S4 工具调用（白名单 v1，仅五类，其余一律不接）
1. 日历查询与建提醒；2. 米家设备查询与可逆控制（灯开关、音箱音量）；3. 天气查询（真实接口）；4. 计时器/提醒；5. 待办记录（写入约定文件并可读回）。
- 做法：逐个实现，每个都必须**回读验证**（如日历建完再查到、灯控制后状态回读变化）。
- 证据：`S4/tool-tests.md`：每类 2 个规定场景的执行日志＋结果回读原文。
- **通过线：10 个场景全过，且无一例「报成功但回读不一致」。**

### S5 语音合成（TTS）播报
- 做什么：Kokoro 接入，sid=58 默认；配置参考：lexicon 用 `lexicon-us-en.txt + lexicon-zh.txt`，rule FST 用 `date-zh.fst + number-zh.fst`，输出采样率 24kHz。长回复按句切分流式播报；播报文本同步推 HUD（S9）与日志；**预留引擎接口**（配置项切换引擎名与参数；IndexTTS-2.5 只留占位配置，不装——原因见 F3）。
- 证据：`S5/` 下 5 条样本 wav＋各自 RTF（Mac 实测）＋样本经 S2 ASR 回转写的 CER。
- **通过线：首句出声延迟 ≤1.5s（短回复）；回转写 CER ≤2%。**

### S6 记忆读写
- 做什么：会话摘要落盘——每轮对话一条结构化摘要（时间、来源终端、用户原话要点、助手动作）；次日可按关键词/日期召回；**写入前脱敏**：凭据、验证码、证件号、银行卡号一律不落盘（先写脱敏规则清单）。只按约定接口读写既有记忆体系，**不许自创平行记忆库**。
- 证据：`S6/memory-test.md`：「今天记、明天问」跨日召回实测 3 条＋脱敏拦截自测 5 条（含敏感样本）。
- **通过线：召回 3/3 命中且内容无编造；脱敏 5/5 拦截。**

### S7 音箱入口（不刷机路线，本章难点） ——
- 路线写死：Mac 中枢**轮询小爱对话记录**（间隔 **3 秒**起步，可配）发现用户新话语 → 走 S3 协议问大脑 → 用**米家接口向音箱播报**回复文本。
- 去重写死：同一话语以记录 id 去重，**绝不重复应答**。
- 播报带固定识别前缀（默认「贾维斯说：」，可配），让用户能区分贾维斯与原生小爱的声音。
- 米家客户端在 Mac 侧用 mijiaAPI 同款方案自建；**登录扫码须用户本人一次**——开工前把这一步连同其他需用户本人在 Mac 前的事项（系统权限等）攒成一张清单交审核，由审核约用户一次办齐。**清单未经确认不许开工 S7。**
- 证据：`S7/speaker-trials.md`：两台音箱各 10 次端到端（说一句→答一句），逐次记录轮询发现延迟、总延迟、成功/失败与原因；外加 1 次「原生小爱抢答」现场记录（如实记，不许粉饰）。
- **通过线：每台成功 ≥8/10；总延迟 P50 ≤12 秒（轮询路线物理下限，不许为达标改数据）；去重零重复应答。**

### S8 微信接入点（Mac 侧半链）
- 做什么：两个可独立验收的半链：①语音文件（silk/amr 转 wav）→ASR→文本；②回复文本→TTS→语音文件。接口桩：约定投递目录与 JSON 信封格式（字段同 S3）。**桥侧接线不归施工方，不许动桥。**
- 证据：`S8/wechat-halfchain.md`：各 5 条样本输入输出对照＋信封样例。
- **通过线：半链 5/5 跑通；明确标注「端到端待桥侧接线」，不许报全链已通。**

### S9 电视 HUD
- 做什么：Mac 起局域网网页服务，电视浏览器打开；四态（待机/聆听/思考/播报）由守护进程状态驱动；卡片：时钟、天气（真实接口）、今日日程、待办、当前播报文本（大字）；断线自动重连；深色低亮度待机页防烧屏（像素轮换或低亮静态）。
- 证据：`S9/` 四态各 1 张电视实拍照片＋服务日志（状态切换时间戳须与 S1/S5 日志对得上）。
- **通过线：四态与语音链状态一致无错位；拔网 30 秒再恢复，页面零操作自愈。**

### S10 常驻化与总验收
- 做什么：LaunchAgent 开机自启；看门狗（进程消失 30 秒内拉起、连续失败 3 次停拉并写告警日志）；日志轮转（单文件 ≤10MB、保留 7 天）；24 小时浸泡运行；10 个规定场景总演练（唤醒问天气、建提醒、开关灯、问昨日记忆、计时、音箱问答×2、微信半链、断网演练、误唤醒演练）。
- 证据：`S10/soak-report.md`：24 小时运行摘要（重启次数、异常清单、资源占用采样）＋10 场景逐场日志索引。
- **通过线：浸泡期零人工干预、崩溃自恢复 ≤30 秒且有日志；10 场景 ≥9 过，失败 1 场须附根因与修复计划。**

## 5. 故障分支与异常处置（逐条实现＋演练证据，不许只写方案）

**F1. Mac 没有物理麦克风**
- 症状：系统设置输入设备只有虚拟声卡（如 BlackHole），无真实输入（实测踩过：Mac mini 无内置麦克风）。
- 根因：硬件缺失，不是软件问题；注意「云端试验台无麦克风」与「Mac 无麦克风」是两回事，必须分别实查。
- 处理：S1/S2 前先补外接麦（USB 麦/带麦耳机/手机临时顶均可），列入 S7 用户清单一次办齐；**不许在无麦状态下用文件喂入的成绩冒充唤醒/远场实测**。

**F2. 原生小爱抢答**
- 现象：对音箱说话，原生小爱先应答，贾维斯的回答是其后经米家播报的第二声。
- 定性：**已知限制，不处置、不粉饰**，S7 现场记录如实记。只能用固定前缀与音色区分，无法阻止第一声；验收按贾维斯链本身成功率计。

**F3. 想用 IndexTTS-2.5 换主链**
- 结论写死：**不换**。官方要求 NVIDIA GPU 约 6GB 显存起、无 CPU-only 支持路径；现有机器无 N 卡，本机未实际跑起推理。Kokoro 继续做实时主链；IndexTTS-2.5 只在 S5 留可插拔接口占位，定位「有 GPU 或 Mac MPS 移植验证通过后才接入的可选高质量/克隆音色后端」。许可为 bilibili 自定义协议（非 Apache-2.0），个人自用无碍，克隆他人声音须本人同意。

**F4. sherpa-onnx 按旧文档写代码跑不通**
- 实测坑：①2.0.x 的 Python API 与旧文档不同——`KeywordSpotterConfig` 类已不存在，KeywordSpotter 改为扁平参数构造；`LinearResampler` 未在 Python API 暴露，重采样需另想办法（正式版用 polyphase）；②`sherpa-onnx-cli` 装完不能直接用，先后缺 `click`、`sentencepiece`、`pypinyin`，逐个补装后 text2token 才跑通；③Kokoro 的 `--kokoro-data-dir` 在 ≥2.0.0 已废弃并被忽略（有 WARNING），实际走 lexicon 路线，不影响结果；④tar 解压刷屏 `Cannot change ownership` 只是属主还原失败，文件完整，可忽略；⑤内存紧张时三环必须逐进程串行跑，同时加载两个模型有 OOM 风险。

## 6. 禁区与红线

1. **不刷机**：两台音箱不刷固件、不 SSH 接管、不装第三方固件，只用米家云端接口正规能力（两台均不在刷机支持型号之列，此路本就走不通）。
2. **不动既有系统**：不改微信桥代码与配置；不动干部桥 v2（不看、不改、不调用）；不碰办公服务器与工作台；不碰直播机的桥与浏览器登录态；不改 Mac 上既有管线（微信直发链、办文巡查、授权小窗点击器、直播工程及其保活名单），冲突先停手回报。
3. **凭据红线**：令牌、密码、密钥不写进代码、日志、回报与记忆文件；米家令牌只存 Mac 本地受限目录（权限 600），回报只许说「已就位/未就位」。
4. **语音不授权敏感动作**：付款、银行登录、对外承诺、给第三方发消息、删除不可逆数据——语音链一律拒绝并回固定话术，此类仍走原有确认规则。
5. **不编造数据**：天气、日程、设备状态必须来自真实接口回读；拿不到就如实说拿不到。
6. **许可合规**：fork 参考项目只许非商用个人使用，保留 LICENSE 与署名、衍生同许可；克隆音色只许用户本人声音或已授权声音，不碰影视角色原声。
7. IndexTTS-2.5 不进 v1 主链，不许为它装重栈拖进度。
8. 已知限制不许宣称已解决：小爱抢答拦不住、轮询延迟数秒级非实时、远场未验前不报数、v1 无克隆音色。
