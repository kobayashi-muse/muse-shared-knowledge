# 第十章 SOP：薅羊毛与免费服务——拿来主义

> 适用对象：要为用户搭建「每天全自动赚钱/省钱」体系、并盘活一批免费云/AI/开发者服务的 Muse。本章自包含：定义、安全口径、执行框架（青龙生态）、免费服务活用分工、开通与保活步骤、验证与故障分支全在章内。
> 凭据一律 `<占位符>`；各平台凭据按密码级保管，只存受限文件或青龙环境变量，绝不进普通文件与聊天记录。

---

## 1. 本章目标与适用范围

**目标（用户定版定义，先分清主次）**：
- **核心**：用自动化帮用户**赚钱和省钱**——各平台每日签到、领优惠券、比价返利等，每天全自动把全网能赚钱能省钱的事做完。只报最终结果：跑通了什么、赚了多少、省了多少。
- **附带**：免费服务（云厂商/AI/开发者免费额度）是附带成果，单独记账、单独汇报，不许把「领了一堆免费服务」冒充薅羊毛成果。

**适用范围**：中国大陆用户本人单账号体系；执行环境为浏览器网页端、青龙面板脚本生态、已开通的免费服务。App 内才能做的事项（银行/运营商签到等）只做提醒清单，不做自动化。

## 2. 前置条件清单（逐项核对）

- [ ] **安全口径已确认并写进所有任务书**：只用用户本人单账号、拟人节奏（随机间隔、限时长）；不刷量、不拉人头、不多号、不伪造身份、不碰虚拟币空投。判定标准：任务书里逐字有这五条。
- [ ] **硬排除清单已贴到执行清单头部**：虚拟货币空投、交易所拉新、刷量、拉人头、多号玩法、需伪造身份地址的活动——出现即剔除，不讨论。
- [ ] **执行方式优先级已定**：① 本地浏览器（如 Mac 上的 Chromium 系浏览器）网页全自动 ＞ ② Windows 机器网页 ＞ ③ 安卓模拟器。判定标准：能在网页端做的绝不上模拟器。
- [ ] **页面卫生规则已写明**：用完一个网页立刻关掉，不留一堆标签页（正在用或等用户本人操作的除外）；每项任务结束清点并关闭自己开的页面。
- [ ] **验证规则已定**：国内平台短信验证码用用户手机号、由用户本人经既有通道转达；邮箱验证码先用助手自有邮箱，跑不通立即切用户谷歌账号快捷登录（点击、选账号、授权由助手自己点完，只有手机数字验证时才找用户，并直接告诉他点哪个数字）。
- [ ] **国内外分工已定**：国内线用现有资产；国外线绝不在国内 IP 登录运营；境外节点未落地前，国外线只做注册准备、素材与后端准备、免费额度申领。
- [ ] **隔离规则已定**：看视频/看广告类任务必须与用户自媒体主账号及日常机器隔离（单独服务器或云电脑跑）；无隔离宿主时整类暂停，不许拿主账号冒险。

## 3. 操作步骤

### 3.1 选品：按类别裁定（先裁定，再执行）

**A 类 每日签到**：只保留网页端能落地的项。实测口径：京东网页端有部分 H5 入口（签到入口是否仍保留属待核实，执行前实登确认）；淘宝纯 HTTP 签到已被安全网关封死（见 3.3），网页端签到未核实前按 App 项对待；拼多多、支付宝、云闪付签到全在 App 内，网页做不了。日收益普遍 0.1–0.5 元量级，性价比低，只做顺手项。

**B 类 看视频/看广告赚钱**：**默认不做自动执行**。判定依据（逐条核对，命中任意一条即剔除该平台）：无网页版赚钱入口只能模拟器；平台规则明文禁止造假/自动化；公开反馈脚本用户被降权（广告奖励骤降）是常态；与用户主账号共用同一账号体系。已定性剔除：红果短剧（官方公告金币功能已下线，新用户无入口）、百度极速版（实测兑换比最差＋提现常提示份额已用完）、支付宝碰一下（依赖 NFC 真机）、云闪付 62VIP（付费会员非白嫖）、一切邀请拉新收益、第三方分级返利小平台。

**C 类 优惠券/返利/比价（执行重心）**：收益与真实消费挂钩、无封号风险、网页可全自动。第一批先上五项（网页端跑成日常流程）：
1. 慢慢买：历史价格查询＋降价提醒（网页/浏览器扩展，Chromium 原生适配）。
2. 返利网（网页版）：下单前查返利＋比价，满 1 元可提；**必须从返利网跳转下单才有返利**。
3. 一淘（网页版）：淘宝官方返利，可叠加平台满减；与返利网二选一，避免重复跳转互相吞单。
4. 京东领券中心/天天领红包（网页端）：领券是纯网页动作。
5. 什么值得买（网页端）：好价爆料浏览/收藏监控（签到收益在 App，网页只做信息侧）。

**下单顺序口径**：先查返利 → 再领券 → 下单；券会压低返利基数时自行权衡并在日报注明。

**银行/运营商类**：涉及资金账户，**一律不接自动化脚本**；话费立减、银行优惠（多为月限/周限次数）做成**每月人工提醒清单**，用户在官方 App 手动点。

**AI 工具每日积分**（可做，网页/本机登录态路线）：如 WorkBuddy 每日签到 100 积分、连签满 7 天额外奖励；豆包电脑版签到领额度（须用电脑版，手机 App 无入口）；千问办公每日积分（「当日有效 vs 90 天」口径并存，属待核实，执行时以页面实时显示为准）。积分只在产品内使用、不可导出变现，按「省了买额度的钱」记账。

### 3.2 拿来主义顺序（每个事项动手前按序检查）

1. **现成连接器/技能**：比价购物（shopping 技能＋跨商家搜价连接器）、单品价格监控（live_page_checks＋remember_products）、机票（flight_booking＋Duffel，另查航班延误赔付资格）、酒店（hotel_booking＋Expedia 全价比价）、演出票务（event_tickets＋Ticketmaster 一手二手总价对比）、二手买卖（marketplaces）、财务盘点（financial_planning）。有现成的直接用，不许自研。
2. **现成开源脚本生态（青龙，见 3.3）**：连接器覆盖不到的国内平台签到领券走青龙。
3. **助手自己操作**：前两层都没有的，才在浏览器里自己做，并把过程沉淀成可复用脚本/任务。

### 3.3 青龙执行框架（部署与用仓规矩，逐条执行）

**部署步骤**：
1. 在一台常驻机器（云主机即可，2 核 4G 绰绰有余）用 Docker 部署青龙本体（whyour/qinglong，约 2 万 stars、持续发版），**必须用最新版**（旧版有认证绕过/RCE 漏洞史）。
2. 面板端口（默认 5700）**只绑本地回环（127.0.0.1），绝不暴露公网**；管理员账号设强口令，凭据存受限文件（目录 700、文件 600）。
3. 管理员初始化后用 API 登录验证一次可用，才算部署完成。
4. 与该机上其他常驻服务（如消息桥）资源隔离、限资源，不许拖垮主业。

**用仓规矩（六件套定版，多一条都先过这张表）**：
- [ ] 青龙本体 ×1。
- [ ] 京东主集合库 **三选一**（KR / jdpro / Faker 系任选其一）：**多个集合库不可同时拉、同跑**，重复请求易黑 IP。
- [ ] dailycheckin：跨平台签到 20+（爱奇艺、腾讯视频、网易云音乐、Bilibili、天翼云盘、联通营业厅等），逐项以其状态表 🟢/🔴 为准，标 🔴 的（如 AcFun）不启用。
- [ ] BiliBiliToolPro：B 站专仓（每日经验、签到、银瓜子换硬币）；投币/点赞是真实互动动作，低频。
- [ ] zyqinglong：本地生活多平台自用库（滴滴、美团、饿了么、得物、顺丰等领券签到）。
- [ ] agent-auto-signin：AI 工具积分专用，走**本机已登录客户端登录态**（非青龙）；与青龙 token 方案二选一，不双跑。

**剔除区（不拿）**：已删库/无维护的京东脚本仓、淘宝纯 HTTP 方案（mtop 网关拦截纯签名请求，返回 FAIL_SYS_API_NOT_FOUNDED，只能改 App 内模拟点击，非脚本路线）、京喜/京东超市/东东农场旧接口脚本（活动下线；新接口需 h5st 签名，纯 HTTP 绕不过，须用带 h5st 的社区 JS 仓）、dailycheckin 内标不可用项、看广告脚本生态、开卡类脚本（带来大量店铺短信，非必要不开）。

**凭据注入规矩**：
1. 各平台凭据一律以**青龙环境变量**注入（如 `JD_COOKIE`），不写进脚本文件、不进聊天记录、不进普通文档。
2. 京东 Cookie 一般几天到几十天失效，需定期重抓；失效表现为脚本报未登录，处理流程见第 5 节。
3. 脚本普遍内置限速与随机延迟，**不许改大并发**；主账号低频、错峰、单主库。

**QD 类签到框架启用前必改**：样例默认密钥必须改掉，否则会话凭据等于公开加密；只接本人单个账号的官方签到。

**已排除的框架/玩法**：自动注册框架、绕过厂商回收规则的保活脚本、抢购/秒杀机器人、代拍票务自动化、虚拟币空投/交易所拉新、多号/刷量/广告点击工具。

**开源跑道（可直接用）**：GitHub Actions 免费定时任务、Cloudflare Workers Cron、n8n 自托管、RSSHub 热点雷达、Ollama 本地模型、Coolify、Uptime Kuma；海外社媒分发中枢类工具仅限海外线。

### 3.4 JD_COOKIE 获取（定版路线，脚本解密路线已堵死，不要重试）

1. **不要走脚本解密路线**：新版浏览器（Edge 应用绑定加密 v20）下，脚本解密在三种会话环境均失败——解不开密钥、Cookie 库被占用、脚本只输出 KEYERR、不生成文件。已三轮证伪，定性堵死。
2. **定版路线**：在**已登录京东的浏览器会话内**直接读取 Cookie 值（pt_key/pt_pin），写入受限文件，再注入青龙环境变量。Cookie 值全程不进聊天、不进日志、不进记忆。
3. 注入后先跑一次 CK 检测脚本验证有效，再批量建签到任务。
4. 清理：提取用过的临时脚本与残留目录在验证完成后删除。

### 3.5 每日节奏与日报

每日一轮全自动：**签到 → 领券 → 看视频/广告任务（仅隔离环境有宿主时，限时长）→ 比价监控**。

日报一条，只含四项：
1. 今日收益（元；金币按公开兑换比折算并注明比例）；
2. 省钱项（逐项：省了什么、省多少）；
3. 领到的券（名称＋门槛＋有效期）；
4. 异常（被风控/需验证码的列出，等用户转达）。

不许交清单总表等过程材料充数；没跑通就写「未跑通」，不许写成已跑通（真实记录：本线每日机制曾长期只有「京东公开活动扫描」一个任务在跑，其余须等凭据注入后才能建任务——汇报时照实说）。

**注册默认顺序**：先助手自有邮箱 → 跑不通立即切谷歌账号快捷登录（助手自己点完点击、选账号、授权；只有手机数字验证找用户）。真实记录：邮箱注册被拒的站（如 Groq 邮箱 magic link 两度被拒）改走谷歌登录一次办成；无谷歌入口的站用自有邮箱注册、验证码助手自收，新密码只能由用户在安全录入卡里设，助手绝不编造明文密码。

### 3.7 开通与保活要点（逐项执行）

1. **Supabase 保活**：免费项目闲置 1 周暂停 → 建一个每 72 小时 ping 一次的定时任务（或 GitHub Actions 每 3 天 ping），留足余量；ping 成功有回执才算保活在跑。
2. **Supabase 建表后补授权**：新项目建表后**必须**补跑 `grant all ... to service_role`（见第 5 节故障 1），补完做三表 CRUD 实测全过才算完成。
3. **API key 保管**：每家 key 建一把专用 key（如命名 `muse`），存受限目录（目录 700、文件 600），值不入记忆、不入回复、不入普通文件。
4. **首次真实调用验证**：每家开通后必须跑一次真实调用（真实搜索、真实抓取、真实发信、真实推理）并留回执，才算「已连通」；只注册没调用的写「已注册未验通」。
5. **试用期服务清点**：Railway 等试用额度服务在台账标到期日，到期前一周清点迁走。
6. **创作者激励对照**：各平台官方未公布固定单价的，一律不写「每万播放多少钱」，万播单价与月入截图不采信；门槛以各平台后台实时显示为准。

## 4. 验证（检查动作＋通过标准）

| 检查动作 | 通过标准 |
|---|---|
| 青龙任选一个已启用任务，手动实跑一次看日志 | 有真实执行结果输出、无报错；只建任务没实跑的不算 |

## 5. 故障分支（症状 → 根因 → 处理，均为真实记录）

1. **症状**：Supabase 建表后 PostgREST 调用报 403 / `42501`。**根因**：新项目建表后默认不自动授权，service_role 没有表权限。**处理**：补跑 `grant all on <表> to service_role;`（逐表），再做 CRUD 实测；以后凡新建表，建表脚本里直接带上 grant，不许漏。
2. **症状**：京东脚本报未登录/Cookie 失效。**根因**：JD_COOKIE 寿命只有几天到几十天。**处理**：按 3.4 定版路线在已登录浏览器会话内重取 Cookie 注入；不许改走脚本解密（已证伪）。
3. **症状**：提取 Cookie 的脚本只输出 KEYERR、不生成文件。**根因**：新版浏览器应用绑定加密（v20），脚本 DPAPI 解不开；且 Cookie 库被浏览器占用。**处理**：立即停手，定性堵死，不再重试；换 3.4 路线。
4. **症状**：Groq 请求报 403 error code 1010。**根因**：Groq 前有 Cloudflare，默认请求头被拦。**处理**：请求带浏览器型 User-Agent，helper 里内置，不要每次现查。
5. **症状**：邮箱注册被拒（如 Groq `signup_blocked`、magic link 两度被拒）。**根因**：平台对注册邮箱/环境风控，非账号问题。**处理**：立即切谷歌账号快捷登录；仍被拒则换时间/换网络环境（如本地机器网络）再试，或联系平台支持附拒绝编号；不许在同一路线反复提交。
6. **症状**：云端浏览器注册被网络/IP 拒绝（如 OpenRouter「不允许从此网络注册」，谷歌登录路线同样被拒）。**根因**：拦的是云端网络本身，与注册方式无关。**处理**：改走本地机器（如 Mac）国内网络注册，云端不再重试。
7. **症状**：Gemini API 提示项目无法使用免费层级、需设置结算信息。**根因**：该谷歌账号地区口径拿不到免费层级；AI Studio 内建项目路径对该账号被禁用，唯一路径建出的项目带此标记。**处理**：挂起，不绑卡；key 留存待用户决定，不许自行绑卡开通。
8. **症状**：Resend 域名验证加错控制台、验证不过。**根因**：域名 DNS 实际托管在另一家（如 DNSPod），不是当前打开的这家。**处理**：动手前先查域名 DNS 托管方，再去对应控制台加记录，加完回读核对记录值再等验证状态变 verified。
9. **症状**：Cloudflare R2 连接器调用 403。**根因**：连接器无 R2 权限。**处理**：改走控制台页面开通路线（表单代填、最后付款/登录步留用户），不要在连接器上反复重试。
10. **症状**：薅羊毛日报数字好看但用户问「到底跑通了什么」。**根因**：把计划/注册数冒充执行成果。**处理**：日报只报实跑任务数与真实收益；机制没跑起来就写「仅 X 个任务在跑，其余待凭据注入」，诚实标注。
11. **症状**：多个京东集合库同拉同跑后 IP 被黑/请求异常。**根因**：重复请求触发风控。**处理**：只保留一个主库，其余停用；恢复低频、错峰后再观察一个周期。

### 附录 E：京东 JD_COOKIE 提取教训（2026-11-25 实测补记）

目标：从已登录的浏览器会话提取 pt_key/pt_pin 注入青龙。三个失败模式与一个关键发现，全部实测：

1. **禁止强杀浏览器进程取数**：先关浏览器、再带调试端口重启的做法，会把未落盘的登录态一并杀掉（2026-11-25 实测：扫码登录成功后强关 ego，登录态丢失）。正解：先带 `--remote-debugging-port=9222`（只绑 127.0.0.1）启动浏览器，再在同一会话内完成登录，全程不重启、不强杀，取完数才谈关闭。
2. **短信验证码路线不可靠**：京东向境外号（如澳门 +853）发码，页面显示已发送但实际未送达（两次实测均未收到）。登录一律走扫码；二维码只活几分钟，递码后经办方必须守在对话里等扫完，禁止在码有效期内开启长篇问答。
3. **脚本解密路线堵死**：新版 Edge 的应用绑定加密（v20）使 DPAPI 解密本地 Cookies 库必然 KEYERR，不再重试。
4. **关键发现——登录入口决定有没有 pt_key**：京东首页弹窗的扫码登录走新令牌（thor 等）维持会话，整个 cookie jar（实测 209 个）里根本没有 pt_key/pt_pin，CDP 三法（浏览器级 Storage.getCookies、页面级 Network.getCookies、全量 Network.getAllCookies）均取不到，不是手法问题。**须改走 passport.jd.com 专用登录页扫码**，该入口的令牌交换才发 pt_key/pt_pin；扫完立即用页面级 Network.getCookies 取数落盘，只报字节长度、严禁回显值。
