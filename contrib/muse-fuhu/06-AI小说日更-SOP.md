# 第六章 SOP：AI 小说日更（番茄＋七猫双平台）

> 本章是操作手册，不是经验概述。只读本章、不看任何其他文件，照步骤执行即可完成「备稿→质检→双平台发布→核对」全流程。本章所有路径、字段、口径均为实测固化值；凡写「写死」处不许自行改动。

---

## 1. 本章目标与适用范围

- 目标：一部连载网文每天发布 1 章，同一章同日发到番茄、七猫两个平台，内容逐字一致（七猫空格例外见故障分支 F1），发布后逐项核对无误。
- 节奏写死：**每天 1 章；前一天备稿并过质检；发布日只做发布，不在发布日写稿。**
- 生产真源：云端 `~/workspace/novel-studio/`。Mac 上有同名原件只留备用，**绝不双跑**（见故障分支 F4）。
- 发布路线写死：**云端浏览器作家专区手工发布**。API 发布管线已搁置（云端取不到两站 Cookie），**不要再试 API 发布**。
- 定时器暂不启用：人工触发、按本章执行，跑稳一周后再议自动化。
- 本章不含：作品名、作品 ID、人物名等具体标识——执行时从真源目录的 `DAILY-ROUTINE.md` 与最新一章 DRAFT 报告中读取，本章只给字段位置与口径，不写具体值。

## 3. 操作步骤

### 阶段 A：备稿（发布日前一天）

**A1. 读细纲定本章规格**
- 打开 `data/outlines/` 下正式细纲，定位本章条目，抄下四项：不可逆事件、章末钩子、标题（纲要期章节无给定标题时，按上一章章末钩子自拟，并在报告中注明自拟）。
- 预期结果：本章规格四项齐全，缺项先停下问细纲，不许自行编造主线事件。

**A2. 写生成提示词**
- 路径：`drafts/yuanbao-prompt-ch-0XX.txt`（0XX 为三位章节号，如 ch-011 写 `yuanbao-prompt-ch-011.txt`）。
- 格式照上一章同名文件，内容必须包含五项：①承接点（上一章结尾状态）；②不可逆事件清单（来自 A1）；③规则边界（见第 6 节红线逐条写进提示词）；④章末钩子（来自 A1，原样落点）；⑤人物锁定名单（从最新 DRAFT 报告读取，名字一字不改）。
- 预期结果：提示词文件落盘，五项齐全。

**A3. 生成正文并落盘**
- 生成方式写死：由子代理按提示词人工生成（生成记录 `engine=claude_subagent_manual`、`used_yuanbao=false`），不使用外部生成工具。
- 路径：`data/chapters/<作品目录>/ch-0XX.md`。
- 格式写死：**第一行是标题行「第X章 标题」**，其后为正文。
- 字数写死：**正文汉字 2200–2800**（质检脚本口径）；总字符参考区间 3000–3400。低于下限不许靠注水凑数，必须补真实情节 beats（见故障分支 F2）。
- 预期结果：正文文件落盘，标题行格式正确。

**A4. 连续性对齐（落笔后、质检前逐条自查）**
- 以**最新一章 DRAFT 报告的「新设定的口径」为准**，逐条核对本章引用：所有编号类固定口径（回执编号、申请号、日期、尾号类标识）必须与报告原文逐字一致，不许改写、不许新编。
- 红线类逐条核对见第 6 节。
- 预期结果：无一处口径漂移；发现与旧章冲突时以最新报告为准，并在本章报告「与大纲的出入」中写明。

### 阶段 B：质检（不过不发，无例外）

**B1. 建事件词表**
- 路径：`data/qc/ch-0XX-events.txt`，格式照上一章同名文件：本章必须出现的事件词/关键物/人名逐行列入（实测每章约 12 个事件词＋人名锁定 3 项）。

**B2. 跑质检脚本**
- 命令：`cd ~/workspace/novel-studio && python3 scripts/qc_chapter.py`（参数照脚本既有用法，指向本章）。
- 质检输出存 `data/qc/ch-0XX-qc.md`。
- 检查项全集（12 类，缺一不算过）：wordcount（总字符）、cjk（汉字数）、事件词（逐个命中）、人名锁定、title（标题行）、banned（禁词）、ocr、opening（开头）、hook（章末钩子）、dialogue（对话）、props（关键道具词）、repeat（重复段）。
- **通过标准：输出 `RESULT: PASS` 且退出码 exit 0。** 任一项 FAIL 就改稿后复跑，直到全过；不许跳过、不许改脚本放行。

**B3. 写生成记录**
- 路径：`data/chapters/<作品目录>/ch-0XX.generate.json`，字段照上一章同名文件逐字对齐：`chars`（总字符）、`cjk`（汉字）、`engine`（固定 `claude_subagent_manual`）、`ok`、`path`、`published`（备稿时固定 `false`）、`qc_pass`（必须 `true`）、`sha256`（正文文件哈希）、`time`、`used_yuanbao`（固定 `false`）。

**B4. 写当日 DRAFT 报告**
- 路径：`~/workspace/novel-studio/CH0XX-DRAFT-YYYYMMDD.md`（日期为备稿日）。
- 固定结构六节：①产出（提示词/正文/生成记录/质检输出/事件词表路径＋sha256）；②字数（总字符＋汉字，注明落在区间内）；③质检结果（逐项列 PASS，首跑 FAIL 的写明改法）；④本章推进的线；⑤**新设定的口径**（后续章节必须沿用，逐条编号写清）；⑥与大纲的出入。
- 红线声明必写：未发布到任何平台、未改动已发布章节、未碰 secrets、未启用定时器。
- 预期结果：报告落盘；下一章执行者只读这份报告即可接上全部口径。

### 阶段 C：发布（发布日当天，番茄与七猫各一个浏览器任务，可同批发，互不等待）

> 两站任务文本都必须带：正文全文（**标题行除外**）、本节对应平台的字段口径、核对要求。正文逐字粘贴，**不许改一个字**（七猫空格例外见 F1）。

**C1. 番茄发布**
1. 进作家专区 → 目标作品 → 章节管理 → 新建章节。
2. **章节序号框：只填阿拉伯数字**（如 `11`）。
3. **标题框：只填标题部分**（如细纲标题原文，不带「第X章」），页面会自动拼成「第X章 标题」。填全称会重复，见故障分支 F3。
4. 粘贴正文全文（不含标题行）。
5. 发布设置：**「是否使用 AI」选「否」**（写死，不许选错）。
6. 内容检测：选**「全面检测」**。
7. 若弹「还有错别字未修改」提示：先看它有没有列出具体字。**未列具体字、且章节列表显示错别字为 0 时，可确认提交**；列出了具体字则先回稿核对，不许硬提交。
8. 提交。预期状态：**审核中**（平台提示预计次日 9 点前出结果）。

**C2. 七猫发布**
1. 进作家专区 → 目标作品 → 新增章节。
2. **标题填全称「第X章 标题」**（与番茄相反，写死）。
3. 粘贴正文全文（不含本地文件的标题行，标题已在标题框）。
4. 提交。预期状态：**待审核**。注意：签约评估未通过时全书章节均为待审核、未进正式审核流程，属正常状态，**不是被退回**，不要误判后重发。
5. **不要打开站内信**（写死）。

**C3. 发布后核对（两站都做完才算发布完成）**
- 回两站章节管理页逐项核对：**章节号、标题、字数、状态**四项与本地记录对上。
- 字数口径：平台显示字数与本地质检字数允许有统计口径差（实测同章两站显示可差几十字），但段落数必须一致（实测核对法：数正文段落数，两边相同才算内容无缺失）。
- 任一项对不上：先截图留证再处理，不许凭记忆报「已发」。

## 4. 验证（发布日收尾，逐项打勾）

| # | 检查动作 | 通过标准 |
|---|---|---|
| V1 | 打开本地 `ch-0XX-qc.md` | 末行 `RESULT: PASS` |
| V2 | 打开 `ch-0XX.generate.json` | `qc_pass=true`、`sha256` 与正文文件实算一致 |
| V3 | 番茄章节管理页 | 本章在列，标题为「第X章 标题」，状态=审核中 |
| V4 | 七猫章节管理页 | 本章在列，标题为全称，状态=待审核 |
| V5 | 两站段落数比对 | 与本地正文段落数一致 |
| V6 | 复核上一章正文文件 sha256 | 与其 DRAFT 报告记录一致（证明没误改已发章节） |

## 5. 故障分支（症状 → 根因 → 处理）

**F1. 七猫提交后正文里的空格消失了**
- 症状：核对时发现正文中若干半角空格不见了，其余文字无变化（实测连续两章均如此）。
- 根因：七猫提交环节自动去掉半角空格，是平台行为，不是粘贴错误。
- 处理：**接受，不重发、不改稿**。在当日记录中注明「七猫侧半角空格被平台自动去掉 N 处，除此无改动」。写稿时可预知此事：不要用半角空格承担断句/对齐功能。

**F2. 质检 cjk（汉字数）不足，其余全过**
- 症状：首跑仅 cjk 一项 FAIL（如 1863＜2200）。
- 根因：情节 beats 不够，正文偏短。
- 处理：补**真实情节段落**扩写——实测有效补法：补核对记录原话与在场人、补函件只列事项的口径段、补等待期细节、补配角复核动作段。补完复跑至全 PASS。**不许**重复段落、改字数统计口径、调低区间。

**F3. 番茄标题显示成「第X章 第X章 标题」**
- 根因：标题框误填了全称，平台又自动拼了一次。
- 处理：按 C1 第 3 步改回只填标题部分。七猫恰恰相反，必须填全称，两站口径不要记反。

**F4. 怀疑双跑（同一章两边都在发）**
- 症状：Mac 侧旧管线或定时任务仍在活动，与云端同日处理同一章。
- 根因：两边状态文件不共享，同日锁定防不了跨机双跑。
- 处理：立即停 Mac 侧；云端为唯一生产口。首次恢复发布时先只发番茄一站、盯守核对无误后再发七猫。

**F5. 发布时登录态失效**
- 症状：作家专区要求重新登录/扫码/验证码。
- 处理：**停下报告**，不反复试、不走 API 绕路。等登录恢复后按 C 阶段重走；当天发不了就顺延一天并在记录中写明，不许为赶节奏跳过质检或核对。

**F6. Cookie/secrets 为空导致登录探测失败**
- 处理：如实报失败，不发任何请求；Cookie 只许 0600 权限落盘，**绝不经聊天明文传递**。

**F7. 七猫全书长期「待审核」**
- 根因：签约评估未通过，未进审核流程（字数门槛实测还差约 9200 字，随日更自然补齐）。
- 处理：正常发布、正常记录，**不为凑字数加更、不重复提交**。

## 6. 禁区与红线

1. 质检未 PASS 不许发布；发布日不许写稿赶工。
2. 不许改动已发布章节的正文文件（每章完工后复核上一章 sha256 不变）。
3. 不许试 API 发布；不许把 Cookie 经聊天明文传递；不碰 secrets。
4. 不许启用定时器（未到启用决策点）。
5. 内容红线（写进每章提示词，质检 banned/人名锁定项兜底）：人物名一字不错；女主不喊母亲「妈」；某关键凭证类道具不向任何人出示、对话不提；男主只认物证、不秒爱、无告白、不对联姻表态；空间规则在第 20 章前最多再揭示 1–2 条；悬置线按细纲节奏回收，不提前写掉后章正戏。（具体名词以最新 DRAFT 报告为准，本章不列明。）
6. 登录失效不硬试；七猫不打开站内信。

## 7. 附录：模板与命令骨架

**质检命令**
```bash
cd ~/workspace/novel-studio
python3 scripts/qc_chapter.py   # 指向本章，输出存 data/qc/ch-0XX-qc.md，以 RESULT: PASS / exit 0 为准
sha256sum data/chapters/<作品目录>/ch-0XX.md   # 与 generate.json 及 DRAFT 报告三方对齐
```

**generate.json 字段骨架**
```json
{
  "chars": <总字符>, "cjk": <汉字数>, "engine": "claude_subagent_manual",
  "ok": true, "path": "data/chapters/<作品目录>/ch-0XX.md",
  "published": false, "qc_pass": true, "sha256": "<正文哈希>",
  "time": "<ISO时间>", "used_yuanbao": false
}
```

**发布任务文本骨架（每站一份，正文全文随附）**
```
任务：在<番茄/七猫>作家专区发布第X章。
标题口径：<番茄：序号框填数字、标题框只填标题部分／七猫：标题填全称「第X章 标题」>

<番茄专属：是否使用 AI 选「否」；内容检测选「全面检测」；错别字弹窗未列具体字且列表为 0 可确认提交>
<七猫专属：不要打开站内信>
完成后回报：章节号、标题、平台字数、段落数、状态，四项逐项写明。
```
