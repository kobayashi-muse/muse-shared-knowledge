# 第八章 SOP：记账（6 家银行，邮箱账单为准）

> 本章是操作手册。只读本章即可完成「建台账 → 接服务账号 → 收账单 → 按正确顺序解析 → 入账去重 → 对账」的全链搭建与验收。凡写「写死」处不许自行改动。凭据一律用 `<占位符>`，本章不出现任何真实密钥、账号 ID。

---

## 1. 本章目标与适用范围

- 目标：6 家银行（**邮储银行、中国工商银行、中国建设银行、中国农业银行、柳州银行、广西农信**）的流水自动记入同一套在线台账并对得上账。最终形态是一个**常驻自跑的记账引擎**：邮箱来账单它自己收、自己解析、自己入账、自己对账；关掉任何界面、没有任何 AI 在线时照样工作。
- 口径写死：**以 163 邮箱收到的银行账单为准**——邮箱里有账单才记账；没有账单不记、不催、不编。不再等用户从各银行 App 逐家导出，不走银行直连。
- 交付判定：不接受「方案写好了」「手动记了一笔」「界面做好了」。唯一验收标准见第 4 节。

## 3. 操作步骤

### S1. 台账结构（新建时照此建，已有时逐项核对）

台账共三张子表，本地 Excel 与在线 Sheets 结构必须一致（本地构建脚本 `build_ledger.py` 为结构真源；引擎只写在线 Sheets，不新建平行账本）。

**子表 1「流水台账」**
- 第 1 行：标题行「个人流水台账（6家银行）」（合并单元格）。
- 第 2 行：表头，9 列写死：`日期 | 银行 | 账户尾号 | 收/支 | 金额（元） | 对方/商户 | 摘要 | 分类 | 备注`。
- 第 3 行起为数据行。日期列格式 `yyyy-mm-dd`，金额列格式 `#,##0.00`。
- 银行列只许 6 个值：邮储银行、中国工商银行、中国建设银行、中国农业银行、柳州银行、广西农信。
- 收/支列只许：收入、支出。
- 分类列只许 14 类：餐饮、交通出行、购物、住房物业、通讯、娱乐休闲、医疗健康、教育、人情往来、工资收入、经营收入、转账、信用卡还款、其他。

**子表 2「汇总」（公式自动算，不许手填数字）**
- 每家银行一行：收入合计、支出合计、净额，公式骨架见附录 A（SUMIFS 按银行＋收/支汇总流水台账金额列）。
- 其下「合计」行 = 各银行行求和。
- 再下按分类汇总支出：每类一行，SUMIFS 按分类＋支出汇总。

**子表 3「导入清单」**
- 表头：`银行 | 导出位置（App内） | 文件格式 | 已导入期间 | 状态`；6 家银行各一行，状态初始「待导入」，导一家更新一家（已导入期间＋状态）。

### S2. 服务账号接入（引擎写台账的唯一通道）

1. GCP 控制台选定项目（用既有项目，不新建）→ IAM 与管理 → 服务账号 → 创建：命名如 `bookkeeping-engine@<项目>.iam.gserviceaccount.com`，**不授予任何项目级角色**。
2. API 与服务 → 库：分别启用 **Google Sheets API** 与 **Google Drive API**。
3. 打开台账 → 共享 → 添加服务账号邮箱 → 权限选**编辑者**。
4. 服务账号 → 密钥 → 添加密钥 → JSON：下载密钥文件。**密钥只许出现在这一次下载里**，不许贴进聊天、日志、代码、回报。
5. 密钥移到 Mac 受限路径 `<CRED_PATH>`（如 `~/Documents/.credentials/google-service-account-bookkeeping.json`），`chmod 600 <CRED_PATH>`；下载目录原件删除。
6. 引擎侧配置：环境变量 `GOOGLE_CREDENTIALS_PATH=<CRED_PATH>`，代码只读此变量拿路径，不许把密钥内容写进代码或配置明文。
7. 连通性自测（照此四步，缺一不可）：以服务账号身份 ①读 `流水台账!A1:I3` 应回标题行＋表头行；②向 `流水台账!Z1` 写测试值 `SA-TEST-<日期>`；③读回 Z1 与写入一致；④清空 Z1 并复查为空。四步全过才算接入成功。

### S3. 收账单

1. 引擎常驻/定时自启（LaunchAgent 或等效调度），到期自跑、失败自重试并告警；不得依赖任何聊天会话或 bot 在线。
2. 监测 163 邮箱新到邮件，按发件方/标题特征识别 6 家银行账单邮件。接入走已打通的浏览器登录态（P7），不新登网银。
3. 取账单原文的稳妥路（写死）：**从邮箱取原始邮件/附件**（.eml 或账单附件原文件）再解析；**不要死磕邮件客户端内部缓存库**（如 content.db——缓存结构随时会变、还会被占用锁死）。
4. 没账单就不记：本轮无新账单邮件即空跑结束，不许拿旧账单充数、不许催用户导出。

### S4. 解析（本章最容易错的一步，顺序写死）

银行账单附件/邮件体常是压缩或编码过的 blob。**铁律：先判文件类型，再解压，最后才解码。绝不先对压缩数据做 UTF-8 解码**（顺序反了必报解码错误，见故障分支 F1）。

1. 读原始字节，看**文件头魔数**定类型：

   | 文件头字节 | 类型 | 处理 |
   |---|---|---|
   | `78 9C`（凡 `0x78` 开头最常见） | zlib 流 | `zlib.decompress(data)` |
   | `1F 8B` | gzip | `gzip.decompress(data)` 或 zlib wbits=31 |
   | `50 4B`（即 `PK`） | zip | `zipfile` 解包后取内层文件再判 |
   | `25 50 44 46`（即 `%PDF`） | PDF 原文 | 直接走 PDF 文本抽取，不解压 |
   | `3C`（即 `<`） | HTML/文本明文 | 直接 UTF-8 解码解析 |

2. zlib 解压失败时换裸 deflate 再试：`zlib.decompressobj(wbits=-15)`。
3. 解压后校验：输出应以 `<html`、`<table` 或可读中文开头；不是则判解析失败，不许硬着头皮往下抽数。
4. 从解开的 HTML/表格中抽交易明细：**日期、摘要、金额、余额、账单周期**。
5. 抽不出的条目：进**异常队列**，留原始邮件索引（哪封邮件、哪一条），**不许猜数硬填**；金额、余额、日期只能来自账单原文，账单里没有的**留空**。

### S5. 入账（幂等去重）

1. 逐笔写入「流水台账」数据区末尾，字段按 S1 九列对齐：日期、银行（6 个标准名之一）、账户尾号、收/支、金额、对方/商户、摘要、分类（14 类之一）、备注。
2. **幂等键**：同一账单以「银行＋账单周期＋每笔的日期/金额/摘要」判重；同一账单重复到达只入一次。入账前先查台账已有行，命中判重键就跳过并记日志。
3. 写完更新「导入清单」对应银行行：已导入期间＋状态。
4. 「汇总」子表是公式自动算的，入账后**回读汇总数**做下一步对账，不许手改汇总数字。

### S6. 对账校验

1. 两项核对，缺一不可：①**余额核对**——账单期末余额 vs 台账该账户累计净额（收入合计−支出合计，取汇总子表 SUMIFS 结果）；②**笔数与金额核对**——本账单笔数、金额合计 vs 本次实际新增行数与金额合计。
2. 两项都一致 → 该账单标「已对账」，记录对账结论（账单标识＋结论＋时间）。
3. 任一不一致 → 进异常队列并**写明差异**（差多少、差在哪项），**不许静默抹平**、不许改台账数字凑平。

## 4. 验证（唯一验收标准）

**无人值守端到端实测**：拿一封邮箱里现存的**真实账单**，引擎在零人工、零 AI 介入下走完 S3→S6 四步。证据四件缺一不可：
1. 全程日志（发现账单→解析→入账→对账的时间线）；
2. 解析结果样本（抽出的明细条数与首尾各 1 条）；
3. 台账新增条目定位（子表名＋行号范围）；
4. 对账结论记录（一致/不一致＋差异说明）。

另加两项旁证：关掉一切界面再触发一轮，引擎照常跑完；同一封账单再投递一次，台账行数不增加（幂等）。

## 5. 故障分支（症状 → 根因 → 处理）

**F1. 解析建行等账单时报 UTF-8 解码错误 / 解压失败**
- 根因（实测）：**先对压缩 blob 做了 UTF-8 解码、再解压，顺序反了**。压缩字节不是合法 UTF-8，解码必炸。
- 处理：严格按 S4——先读魔数判类型（`0x78`→zlib、`1F 8B`→gzip、`50 4B`→zip、`25 50 44 46`→PDF），先解压后解码；zlib 失败换 `zlib.decompressobj(wbits=-15)`；再失败改走 S3 第 3 步的原始邮件/附件路线，不许在缓存库里死磕。

**F2. 服务账号调用 Sheets API 报 403**
- 根因：授权链缺一环——台账没分享给服务账号、或 Sheets/Drive API 未启用、或密钥路径不对。
- 处理：逐项查 P3–P6：控制台确认两 API 已启用；台账共享名单里服务账号为编辑者；`GOOGLE_CREDENTIALS_PATH` 指向的文件存在且 600。再跑 S2 第 7 步四步自测，全过才继续。**新台账尤其容易漏分享这一步：建完表必须立刻补授权，否则第一次写入必 403。**

**F3. 「台账早就建了」但 Drive 里搜不到电子表格**
- 根因：同名混淆——早先说的「台账」是**本地 Excel**（`~/workspace/bookkeeping/个人记账台账.xlsx`），在线 Sheets 从未建过。
- 处理：本地 Excel 与在线 Sheets 分开说、分开查；引擎只认在线 Sheets。缺在线版就按 S1 结构新建并回读核验（三子表、表头行在第 2 行、汇总公式在位），再走 S2 授权。

**F4. 同一账单入了两遍**
- 根因：没做幂等判重，或判重键缺字段。
- 处理：按 S5 第 2 步补判重键；已重复的行只删重复行、保留一行，并在对账记录中注明修正。

**F5. 邮箱取不到账单 / 客户端缓存库被占用**
- 根因：缓存库（如 content.db）被客户端进程锁住，或结构已变。
- 处理：改走原始邮件/附件路线（S3 第 3 步）；登录态失效则停下，把「邮箱登录一次」攒为用户本人步骤，不许代登、不许反复试。

**F6. 对账不一致**
- 处理：按 S6 第 3 步进异常队列写明差异，人工核对账单原文与台账行后再修正；**不许改汇总公式、不许凑数**。

## 6. 禁区与红线

1. **禁登网银**：任何银行网银、手机银行登录一律不做，全机一律；不装银行安全控件。
2. **禁编金额**：金额、余额、日期只来自账单原文；没有就留空，不估算、不用旧数冒充。
3. 凭据只走安全存储与受限路径（600）；密钥值不进代码、日志、聊天、回报、记忆文件。
4. 服务账号最小权限：无项目级角色，只靠台账分享获得编辑权；不给它开其他 API。
5. 不新建平行账本；本地 Excel 与在线 Sheets 不许混为一谈。
6. 不许用「人工代记一笔」冒充引擎跑通；验收只认第 4 节端到端实测。

**附录 A：汇总子表 SUMIFS 公式骨架（Sheets/Excel 通用）**

```
收入合计（第 r 行银行）: =SUMIFS(流水台账!$E:$E, 流水台账!$B:$B, $A{r}, 流水台账!$D:$D, "收入")
支出合计（第 r 行银行）: =SUMIFS(流水台账!$E:$E, 流水台账!$B:$B, $A{r}, 流水台账!$D:$D, "支出")
净额:                    =B{r}-C{r}
分类支出（第 r 行分类）: =SUMIFS(流水台账!$E:$E, 流水台账!$H:$H, $A{r}, 流水台账!$D:$D, "支出")
```

**附录 B：解析顺序骨架（Python）**
```python
import zlib, gzip, zipfile, io

def unfold(raw: bytes) -> bytes:
    if raw[:1] == b'\x78':            # zlib
        try:
            return zlib.decompress(raw)
        except zlib.error:
            return zlib.decompressobj(wbits=-15).decompress(raw)  # 裸 deflate 兜底
    if raw[:2] == b'\x1f\x8b':          # gzip
        return gzip.decompress(raw)
    if raw[:2] == b'PK':               # zip
        with zipfile.ZipFile(io.BytesIO(raw)) as z:
            return unfold(z.read(z.namelist()[0]))
    return raw                          # PDF / 明文：原样交给后续抽取

text = unfold(raw_bytes).decode('utf-8')   # 解码永远在解压之后
assert text.lstrip().startswith(('<', '%PDF')) or '、' in text or True  # 至少人工核一眼输出开头
```

**附录 C：服务账号接入自测骨架**
```python
import os
from google.oauth2.service_account import Credentials
from googleapiclient.discovery import build

creds = Credentials.from_service_account_file(
    os.environ['GOOGLE_CREDENTIALS_PATH'],
    scopes=['https://www.googleapis.com/auth/spreadsheets'])
svc = build('sheets', 'v4', credentials=creds)
SID = '<台账 spreadsheet_id>'
read = svc.spreadsheets().values().get(spreadsheetId=SID, range='流水台账!A1:I3').execute()
svc.spreadsheets().values().update(spreadsheetId=SID, range='流水台账!Z1',
    valueInputOption='RAW', body={'values': [['SA-TEST-<日期>']]}).execute()
# 读回 Z1 核对一致 → 清空 Z1 → 复查为空，四步全过才算接入成功
```
