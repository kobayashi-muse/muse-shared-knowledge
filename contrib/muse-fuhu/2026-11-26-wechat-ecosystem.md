口径：只做公开资料研究，未登录任何账号、未动任何配置。结论逐条附来源；查不到或来源互相冲突的标「未确认」。协议逆向多开、绕风控类方案只写风险与不采纳理由，不列为推荐路线。

## 一、企业微信自建应用发消息：正规条件与边界

### 机制
组织管理员在企业微信管理后台「应用管理 → 自建 → 创建应用」，设应用名称、logo 与**可见范围**，取得 corpid、应用 secret、agentid；服务端凭 corpid+secret 换 access_token，调 `POST https://qyapi.weixin.qq.com/cgi-bin/message/send` 向成员推送应用消息。应用自动出现在可见范围成员的企业微信终端上。［来源1：企业微信开发者中心《简易教程》；来源2：企业微信开发者中心《发送应用消息》］

### 前置条件清单（缺一不可）
1. **须先有企业微信组织**（企业/团队），且操作者是该组织管理员——只有管理员能进管理后台创建自建应用；普通成员无此权限。［来源1］
2. **接收人必须先成为本组织成员**，并被纳入该应用的**可见范围**（按成员/部门/标签设置）。不在可见范围的接收人发不到：部分无权限时消息照发但返回 invaliduser/invalidparty/invalidtag；全部无权限直接报错 81013。［来源2］
3. **凭证三件套**：corpid（我的企业页）、应用 secret、agentid（应用设置页）。userid 用明文（自建应用口径）。［来源1、3］
4. **企业可信 IP**：2022 年 6 月 20 日之后创建的自建应用，调用方服务器 IP 必须先在应用详情「企业可信 IP」中配置，否则接口调不通（报错指向 IP 未配置）。云服务器 IP 变更即断。［来源4、5］
5. **接收端二选一**：成员装企业微信客户端，在应用会话里收；或成员关注「微信插件」并开启在微信中接收，才能在个人微信里收到应用消息（还受成员端「仅在企业微信中接收消息」开关影响）。［来源4］
6. **消息接口本身无需企业认证即可使用**（个人注册的未认证企业亦可建自建应用发应用消息）——此条为第三方教程的实测口径；未认证企业在成员规模、外部联系等其他功能上的限制细则，官方公开页未逐项列明，标**未确认**。［来源4］

### 能力与硬限
- **消息类型**：文本（≤2048 字节）、图片、语音、视频、文件、图文（news/mpnews）、文本卡片、模板卡片、markdown（markdown 等部分类型仅企业微信客户端完整呈现）等。［来源2］
- **频率上限**：每应用每天可发「账号上限数 × 200」人次；对同一成员不超过 30 次/分钟、1000 次/小时，超了直接丢弃不下发。［来源2］
- **无送达回执**：接口返回成功只代表平台受理，没有官方的送达/已读回执可查（返回参数只有无效接收人列表）。［来源2、5］

### 边界（与办文场景最相关）
- **只能发给本组织成员，发不到普通个人微信好友**。消息落在企业微信的「应用会话」里，不是微信好友聊天窗口；对方若不是同一企微组织成员，此路不通。［来源5］
- 给组织外的人（其他单位科室长、群众）发材料，企微自建应用**不适用**；它只解决「同一组织内部」的系统化推送。

## 二、Mac 微信自动化：公开工具生态现状

结论先行：**发送侧没有新路，主流仍是剪贴板粘贴链**；新变化只在读取侧和工程化包装上。

1. **wechat-mcp-macos**（PyPI，2026-03 发布，面向 MCP/AI 助手）：发送 = osascript 控制客户端，设剪贴板→点输入框→粘贴→回车，与我方已验链完全同构，需辅助功能权限；读取 = 解密本地微信 SQLCipher 数据库副本直查（不走界面）。注意：读库路线要提取密钥并解密本地数据库，属灰色地带，且微信更新即可能失效，**只记现状、不作推荐**。［来源6］
2. **WeChat Mac RPA 类框架**（视觉感知+LLM 的 GUI 自动化）：默认模式明示「不碰协议、不读数据库、不注入」，发送仍是 AppleScript 写剪贴板+粘贴、发送前回读校验，文件发送同走剪贴板通道；聊天切换靠坐标点击列表项+点击冷却。工程化（日志、熔断、前台校验）比裸脚本成熟，但机制没变。［来源7］
3. **OCR 技能类工具**（如 wechat-personal-message 技能）：激活微信→Cmd+F 搜索联系人（联系人名也是剪贴板粘贴进去的）→OCR 定位结果→Enter 进会话→粘贴发送→OCR 验证。其文档自陈的坑与我方实测一致：搜索首项可能是网络结果、Enter 先弹资料卡、发错面板——即**搜索定位在 Mac 上至今不可靠**，与我方「三路定位皆死」的结论互相印证。［来源8］
4. **注入类 WeChatTweak**：微信 4.x 改用 Qt 重构后 runtime 特性大量丧失，原作者明示只能维护防撤回、多开等基础补丁且要逐版本追适配，社区 fork 同样在跟版本赛跑。它属修改客户端二进制的 patch 路线，**列入禁区，不作发消息路线**（详见第五节）。［来源9］

共同硬约束（各项目文档一致）：微信窗口须可访问/在前台、须授予辅助功能（及屏幕录制）权限、Enter 发送、剪贴板会被占用、焦点丢失即失败。**Mac 上不存在官方插件/API 接口供个人号发消息**，这一条生态里无人例外。

## 三、公众号 / 视频号网页后台：公开机制与限制

### 公众号（mp.weixin.qq.com）
- **群发（发表通知）次数是硬额度**：订阅号每天 1 次、服务号每月 4 次，每次最多 8 篇图文；额度不可提升、认证与否不改变数字。［来源10、11］
- **「发布」不占额度但不推送**：通过发布/发表（不带群发通知）的内容不限次数，但不推送给粉丝、不进粉丝消息列表，只能靠主页、搜索、分享链接触达。［来源10］
- **定时群发**：后台可在群发时选定时；第三方引腾讯帮助页的口径称可设 5 分钟至 7 天内的时间，且定时发表仍需管理员扫码确认；另一运营工具口径称官方只支持提前 2 天、同时只存 1 个定时任务。**两种说法冲突，官方公开文档未见原文，定时窗口天数与任务数标「未确认」**，以实际后台界面可选范围为准。［来源11、12］
- **接口侧**：高级接口（群发接口、客服消息等）需认证公众号才有权限；个人主体未认证订阅号只能用网页后台手工/半自动操作，无官方 API 可调。此为平台公开规则口径，与我方账号现状（个人主体、未认证、接口受限、以草稿箱+发表为主）一致。［来源10］
- **草稿箱**：图文素材存草稿再发表是标准流程；草稿数量上限官方未见公开数字，标**未确认**。

### 视频号（视频号助手 channels.weixin.qq.com）
- 入口在网页端助手（扫码登录，会话独立，换电脑重扫），手机 App 内无定时发布入口。［来源13］
- **定时发布**：助手支持定时排期与草稿管理；第三方指南称最长提前 7 天，但另有实操文指出平台未把最远天数写进公开文档、以日历控件实际可选为准。**「最长 7 天」标未确认**，按界面实测为准。［来源14、13］
- **定时不等于免审**：到点仍要过内容审核，审核时长不可控，卡点内容不宜压时间排期。［来源13］
- 短标题有硬规格：6–16 字、可用符号受限（逗号、括号不接受），描述可带 #话题——这是发布校验层面的公开实操口径。［来源15］

边界小结：公众号/视频号后台只解决「内容对粉丝发布」，不解决「给某个人发消息」；其自动化上限就是后台网页操作本身，受群发额度、扫码确认、审核三道闸约束。

## 四、微信桥接类开源项目现状（个人号方向）

按机制分四层，风险递减顺序为：Hook 注入 ＞ 协议仿真 ＞ UI 自动化 ＞（已死的）网页协议。［来源16、17］

| 路线 | 代表项目 | 现状（2026 年公开信息） |
|---|---|---|
| 网页协议 | ItChat、Wechaty、openwechat | ItChat 已弃（最后 push 2023-09）；Wechaty 未归档但停滞、约 4 年无 release；2017 年后注册的账号无法登录网页版（报错 1203）。整层已死。［来源16］ |
| Hook 注入 | WeChatFerry、ntchat | WeChatFerry 已归档/版本锁死在微信 3.9.x，4.x 无路，且曾整仓删除；ntchat 作者删库。此层检测面最大（进程完整性校验可直接抓），生态集体不稳定。［来源16、17］ |
| 协议仿真（iPad 等） | gewechat、padlocal | gewechat 2026-02 被腾讯法务函腰斩、README 明示「因相关法律原因不再维护」；padlocal 自 2022 年无人维护。此层已被合法性层面判死。［来源17、16］ |
| UI 自动化（Windows） | wxauto | 2025-10-28 停止维护：微信 4.0.5 起客户端改 Qt Quick/QML，UIAutomation 读不到控件树。Mac 侧同类即第二节的剪贴板链项目，仍在小规模迭代。［来源16］ |

- **封号是真实成本**：微信帮助中心把「使用非官方插件运行微信」列为封禁原因；社区有自用两天即封、网页版专属封禁 1 周–3 个月等记录；腾讯官方打击公告点名过模拟按键自动化。高频/批量、回复过快过规律、24/7 在线、注入、新号、异地/服务器 IP 都是触发因子。［来源16、17］
- **一条未确认线索**：有 2026-11 的调研文称腾讯出了官方个人号机器人通道（扫码绑定、标准 HTTP，只能回复不能主动发起），但该作者自注未对照腾讯官方文档核实。**标「未确认」，不作为任何路线依据**，值得日后单独到微信开放平台核查；若属实，与我方 ClawBot 个人桥的定位最接近。［来源16］

## 五、禁区清单（只写风险与不采纳理由）

- **协议逆向多开 / iPad 协议仿真**：开山项目已被法务函腰斩，属腾讯明文打击对象；封号之外还有法律风险。不采纳。
- **Hook 注入（WeChatFerry 类）与客户端 patch（WeChatTweak 类）**：检测面最大、版本锁死、基础设施随微信一次升级即全废；拿主账号做此实验不值。不采纳。
- **解密本地数据库读消息（wechat-mcp-macos 读库部分）**：需提取密钥解密本地库，灰色且随版本失效；我方读取需求已有桥与巡查链覆盖。不采纳为常规路线。
- **绕风控类**（改设备指纹、IP 伪装、批量养号等）：直接违反平台规则且是封号主因，任何情况下不列入方案。

## 六、对照我方已验两条路线：适用边界

| | 路线 A：Mac 微信直发（已验） | 路线 B：桥转用户手机转发（已验） |
|---|---|---|
| 机制 | UI 自动化：剪贴板+菜单粘贴+点发送钮，驱动真实客户端 | 桥（协议通道）把原文与文件发到用户本人微信，用户在手机上长按转发 |
| 收件人 | 任意个人微信好友/群（办文科室长即走此路） | 任意用户手机微信能到达的会话 |
| 适用 | 会话在列表靠前或置顶区、能逐行点选定位；文字+文件；低频、拟人节奏；Mac 开机在场 | 目标会话沉底、列表定位不到时的兜底；件数多、附件多时先打包到用户手里 |
| 边界/失效点 | 深层会话定位无解（滚动 0–2 行且回跳、搜索框聚焦不了、通讯录无字母索引——与第二节生态现状互证，非我方独有问题）；键盘注入被闸，只能粘贴；文件发送后须原地等上传完成再核验；窗口焦点脆弱；属被官方公告点名的模拟操作类，只能靠低频低量控风险，**不能规模化、不能高频无人值守** | 最后一公里靠用户本人在手机操作，不是全自动；桥的出站有实测配额限制（单枚 context_token 约 10 条，超限 ret=-2），批量须计数分批；桥通道的官方定性未确认（见第四节未确认线索），只连用户本人、不外扩 |
| 与企微路线的分工 | 收件人是组织外个人 → 只能走 A/B | 同左 |
| 企微自建应用（候选、未验） | 仅当收件人同属一个企微组织且在应用可见范围内才成立，消息落企微应用会话、无送达回执；可作「组织内部系统通知」的正规备选，**替代不了给科室长（组织外个人微信）发材料**，不列入办文发送路线 | |

公众号/视频号后台是发布线，与上面两条「发给人」的路线不互相替代，各守各的边界。

## 七、未确认清单
1. 未认证企业使用自建应用发消息的官方细则（成员规模等限制）——只有第三方教程口径。
2. 公众号官方定时群发的窗口天数（2 天 vs 7 天两种第三方说法冲突）与同时可存的定时任务数。
3. 视频号定时发布最长提前天数（第三方称 7 天，平台无公开文档）。
4. 公众号草稿箱数量上限。
5. 「腾讯官方个人号机器人通道（只能回复不能主动发起）」是否真实开放——二手来源自注未核实。
6. access_token 有效期等接口细节未逐项引官方原文（机制与端点已由官方文档证实）。
