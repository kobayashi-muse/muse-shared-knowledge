# 第七章 SOP：微信小程序与工作台同步

> 本章是操作手册。只读本章即可完成「核对线上版本口径 → 只读比对工作台与小程序 → 补注册/新建页面 → 本地编译验证 → 上传开发版 → 回后台核对」全流程。凡写「写死」处不许自行改动。

---

## 1. 本章目标与适用范围

- 目标：定期（每周一约 10:00）只读浏览 Web 工作台各业务板块变化，把适合进小程序的功能同步进小程序：自己完成开发、上传开发版、（在口径允许时）提审发布，全程不问用户。
- **工作台本体归另一个维护方：只读浏览，绝不改动其任何文件、页面、数据。** 这是本章第一红线。
- 小程序真源在 Mac 本地：`/Users/apple/WorkBuddy/小程序开发/miniprogram`（下称「真源」）。所有开发只在真源上做。
- 执行者若为被派单的研发 AI（如 WorkBuddy）：派单前置写死——会话权限选「允许完全访问」，模型选「自定义模型」组内 **GLM-5.2**；不许用顶格「极致」模型；**积分状态不作为派单前置，不查、不等**。

## 3. 操作步骤

### S1. 先核线上版本口径（每轮第一步，顺序写死）

1. 进 MP 后台「版本管理」页（`mp.weixin.qq.com` → 小程序账号 → 版本管理）。
2. 逐栏抄录三项原文：**线上版本**（版本号＋发布者＋发布时间＋项目备注）、**审核版本**（有则抄版本号与状态；无则抄状态原文，如「你暂无提交审核的版本或者版本已发布上线」）、**开发版本**（版本号＋提交时间）。
3. 判定口径：
   - 以**后台实查**为准。任何旧快照、旧记忆里写的「X 在审 / 线上是 Y」一律作废，不许沿用（见故障分支 F2）。
   - **停止规则（写死）**：若本轮计划要动的那一版已经审核通过并发布为线上版本，本轮开发与上传**全部停止**，只输出待办清单，等排期指令。理由：继续开发会顶替/干扰线上与审核状态。
   - 若已有版本在审核中：不顶替，只传开发版。
4. 预期结果：一份本轮版本口径记录（三栏原文），写进本轮快照。

### S2. 只读比对（工作台 vs 小程序）

1. 工作台侧：只读打开工作台，导出/抄录其导航配置全量路由清单（实测基准：工作台 `core.js` NavConfig 共 **69 条路由**；同时抄侧栏「我的收藏」模块与各分组模块名）。
2. 小程序侧：读真源 `app.json`（全部页面，实测约 198 个页面）与 `utils/modules.js`（MODULES 注册表，实测 69 条）。
3. 三方对照（工作台路由 × app.json 页面 × modules.js 注册），产出两张清单：
   - **缺失清单**：工作台有、小程序缺的路由，逐条写：来源板块、路由名、小程序建议落点（分包路径）、预计改动文件、复杂度（低/中）。
   - **独有清单**：小程序有、工作台无的，标注「保留不动」，不许顺手删除。

   **B 组（页面文件不存在，需新建页面＋注册，复杂度中）：**

6. 与办公定位无关的娱乐类页面（如八字排盘页）不同步，登记即可。
7. 预期结果：本轮缺失清单与独有清单落盘，作为开发与回报依据。

### S3. 开发（按清单逐项，先 A 组后 B 组）

1. **A 组补注册**：只改两处——`app.json` 对应分包的 `pages` 数组加页面路径；`utils/modules.js` 的 MODULES 加同名注册条目（字段照相邻同类条目复制改名）。**不改页面业务代码本身。**
2. **B 组新建页面**：在落点分包下建页面四件套（`.js/.json/.wxml/.wxss`），结构照同分包内同类页面复制后改业务；同样完成 app.json＋modules.js 注册。工作台本体只读参照，**不许改工作台文件来「配合」**。
3. 网格组长信息（真源内写死的 FEN_META）：**按既定决定不改**，哪怕已过时也不动。
4. 分包名含已变动班子人名：仅为开发者工具内显示名，不影响线上界面；是否改名须先核对现行分工口径再决定，不许自作主张改。
5. 党建/诉求类内容：**个人主体不能提审**，此类页面可开发可传开发版，提审环节跳过并在回报中注明。

### S4. 本地编译验证

1. 开发者工具打开真源项目 →「信任并运行」→ 等编译完成、模拟器正常渲染工作台首页。
2. 逐个点开本轮新增/补注册的页面，确认能打开、不白屏、不报模块缺失。
3. 编译崩溃或项目打不开 → 先走故障分支 F1，不要反复重启硬试。

### S5. 上传开发版

1. 上传入口：开发者工具菜单「工具 → 上传」（快捷键 ⇧⌘U）。
2. **版本号**：线上版本顺延一位（如线上 2.8.12 → 开发版 2.8.13）。
3. **顺序写死：版本号最后改。** 先填备注、其他项，最后改版本号，改完**直接点上传**。原因：改完版本号再去点备注框，版本号会被工具刷回上次值（见故障分支 F3）。
4. 上传表单输入：版本号/备注框可用键盘输入；上传按钮须用元素点击，坐标点可能点不中。
5. 本轮口径若为「只传开发版不提审」：上传完即停，**不点提审、不点发布**。

### S6. 回后台核对与落快照

1. 回 MP 后台版本管理页，确认开发版本栏出现新版本号与提交时间。
2. 写本轮基线快照到 `~/workspace/miniprogram-sync/基线快照-<日期>.md`，固定内容：版本口径三栏原文、功能清单变化、差异与同步结论、未完成项、改动文件清单（无改动也要明写「无代码改动」）。
3. 派单执行时另交五段回报：版本实查结果、同步清单、开发完成情况、上传结果、未完成项与卡点。

## 5. 故障分支（症状 → 根因 → 处理）

**F1. 开发者工具一打开就报「编译进程崩溃，请重启工具重试」，重启无效**
- 根因（实测）：**项目登记路径被误设为用户主目录**（导入时选错层级），工具把整个主目录当项目扫描，压崩编译进程。项目卡片上路径一眼可查，先看卡片路径对不对。
- 处理（写死，不要试导入对话框与键盘定位，两条路实测走不通）：
  1. 菜单「项目 → 查看所有项目」打开项目列表窗；
  2. 双击正确项目卡片（路径应为真源路径）；
  3. 点「信任并运行」，即打开正确项目并正常编译。
- 若登记文件已被改坏需手工修：先 ⌘Q 完全退出工具；登记存于 `~/Library/Application Support/微信开发者工具/<hash>/WeappLocalData/`，涉及 `reduxPersist:projectList`（localstorage 文件）、last_all_projects、last_select 三处（键名对照在同目录 `hash_key_map_2.json`）；改前三文件各留一份 `.bak-<日期>` 备份，再把三处路径改回真源路径（projectList 里键名、projectId、projectPath、projectName 一并改）。
- 注意复发点：工具运行时会把 last_select 按当前打开项目覆写；修好后把残留的错误项目窗口关掉（用窗口左上角关闭按钮，⇧⌘W 不关窗口），防再次被覆写。

**F2. 快照/记忆说某版本「在审」，实查却已上线（或相反）**
- 根因：版本状态变化快，旧快照口径滞后（实测：基线快照写 2.8.12 在审，实查已于数日前审核通过并发布为线上版本）。
- 处理：一律以 S1 后台实查三栏原文为准；触发停止规则就停开发，只出清单。**不许拿旧口径继续排期。**

**F3. 上传时版本号被刷回旧值**
- 根因：改完版本号后再点备注框，工具会把版本号刷新回上次值（实测改 2.8.13 被刷回 2.8.12）。
- 处理：按 S5 顺序——备注先填，版本号最后改，改完直接点上传，中途不再点其他输入框。

**F4. MP 后台账号菜单点不开、切不到小程序账号**
- 症状：设备通道下左下角账号菜单点不开，焦点在标签页间跳变，回车键被通道拦截。
- 处理：不硬试。登记为本轮未完成项，下轮优先核查；在回报中如实写「未核查」，不许写「在审」充数。

**F5. 工作台侧栏菜单展开不全**
- 处理：通道焦点不稳时不硬翻；未展开部分在快照中记为「基线缺口，下轮补核」，不许凭猜补全模块清单。

**F6. 顺手关标签页误关用户在用页面**
- 处理：本轮新开的标签页若关不掉就留着并在快照中登记，不许为关标签反复操作误伤培训页、工作台页等在用页面。

## 6. 禁区与红线

1. **工作台本体零改动**：只读浏览，不点修改/提交，不改其文件与数据。
2. 已有版本在审核中不顶替；已上线版本触发停止规则，不许硬开发硬上传。
3. 党建/诉求类内容个人主体不提审。
4. FEN_META 网格组长信息不改（既定决定）。
5. 小程序独有页面不删（只标注保留）。
6. 派单会话未设「允许完全访问」＋GLM-5.2 前不派活；不查积分、不等积分。
7. 上传只传开发版时不提审、不发布；提审/发布须有明确口径才做。
