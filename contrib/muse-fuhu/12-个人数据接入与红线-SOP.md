# 第十二章 SOP：个人数据接入与红线

> 适用对象：要把用户散在邮箱、手机、智能家居、政务/教育平台里的数据逐项接进来、汇总归档的 Muse。本章自包含：接入顺序、逐项判定标准、各渠道的真实卡点与处理、四条业务红线的判定法。
> 全章不写任何密码、令牌、验证码值、证件号、手机号、邮箱与财务明细；渠道汇总只记「渠道与状态」，不记凭据。

---

## 1. 本章目标与适用范围

**目标**：把用户圈选范围内的数据逐项接入并归档到个人数据档案（目录如 `<工作区>/personal-data-archive/`），每项以**实际读到数据**为接入成功的唯一标准；同时守住红线：家人数据须本人同意，无合法接入路径的渠道不在范围，红线业务再三要求也不做。

**适用范围**：邮箱足迹与账单、手机数据（日历/通讯录/位置/健康/提醒）、智能家居、学时与继续教育记录、政务类账号（社保/公积金/交管等）。不适用于：他人（家人、同事）未同意的数据；内网渠道（纪委监委/公检法内网、原始轨迹/通话详单——无合法接入路径，直接不在范围）。

---

## 2. 前置条件清单（逐项核对）

- [ ] **接入范围已由用户圈选定版**：接入清单逐项列明（渠道、数据内容、用途），未圈选的不接。判定标准：说不出「共 N 项、已接通 M 项」的＝清单未定版。
- [ ] **渠道汇总文件已建**：`<个人数据档案目录>/已接通渠道汇总.md`，口径写死：**只记录渠道与状态，不记录任何密码、令牌、验证码**。
- [ ] **凭据保管通道已定**：登录信息只进安全存储（保险库），不进汇总文件、不进记忆正文、不进聊天。判定标准：在汇总与档案文件里 grep 不到任何凭据值。
- [ ] **家人数据同意状态已逐人确认**：每位家人单独标注「已同意/未同意/未询问」；未同意的其数据一项都不接。
- [ ] **红线清单已贴到工作区**（见第 6 节）：接入与日常办理中随时对照。

## 3. 操作步骤

### 3.1 接入总顺序（按此序推进，每项独立销账）

1. **先接有原生连接器的**：邮箱（Gmail）、日历、表格、文档、通讯录、任务等——连接后立即实读一条数据验证（见第 4 节），读不到不算接通。
2. **再接浏览器方式可登录的**：无原生连接器的邮箱（如 163 邮箱）走浏览器登录（登录信息存安全存储），只读查邮件；银行账单类数据以**邮箱收到的账单为准**建台账，不走银行直连、不在任何机器上登录网银。
3. **设备侧数据**：手机（日历、通讯录、位置、健康、提醒事项）经配对设备通道逐项实读；智能家居经云端自建连接（扫码登录取令牌）拉设备清单。
4. **政务/教育类**：社保、公积金、交管等需扫码登录的，**攒齐后请用户一趟过**（一次报齐所有要扫的码，逐个标注哪个账号、扫完能做什么）；学时记录从平台逐项核（见 3.4）。
5. **接不了的当场定性**：封闭系统、无接口、数据在他人账号内等，写明根因与「需谁配合」，列入「未接通/待条件」节，不许反复重试、不许写成已接通。

### 3.2 邮箱足迹与记账数据接入

1. 以邮箱为枢纽盘点账号足迹：逐封/逐类梳理注册与账单邮件，产出《邮箱账号足迹清单》存档案目录，分组列明，待确认项单列一区，**交用户确认后才算入档定版**。
2. 记账：6 家银行台账（或用户实际银行数）以邮箱账单为准——邮箱里有账单再记账，不等用户逐家导出；台账结构定版字段：日期／银行／账户尾号／收/支／金额／对方或商户／摘要／分类／备注；汇总用公式（如 SUMIFS）自动算，不手填总数。
3. 邮箱登录信息只存安全存储；汇总文件里只写「浏览器方式登录可用（非原生连接器）」。

### 3.3 手机数据接入（逐项判定，真实卡点照此处理）

逐项实读，通过标准见第 4 节。已实测的卡点与判定法（照抄执行，不要重复踩）：

- **日历/通讯录/位置**：经设备通道实读通过即销账；通讯录以全量同步条数为准（如同步日志显示总条数），不许只读到几条就报「已接通」。
- **健康数据**：若用户已在系统设置里打开全部健康类别、同步重跑多次仍为 **0 条**——根因通常是 **Muse 自身连接流程未完成**（须用户走连接链接确认），**与设置类别开关无关**。处理：把连接链接发给用户走完，再查同步状态，条数 **>0** 才算接通；**不许再让用户反复检查设置开关**。另注意：健康页里见到 Muse 在列只是「申请过」的登记，**不等于已授权**，判定只认实际同步条数。
- **提醒事项**：授权弹窗可能弹出后未停住（判定为「未授权、待触发」，不是用户拒绝）。处理：等用户回到 Muse 界面时再触发一次，用户点「允许」后实读验证；不许连环触发骚扰。
- **家人设备**：儿童手表（封闭系统无对外接口）＝接不了，定性关闭；家人的手表/健康数据在其**本人账号**内，须其本人配合转出，未配合前列「待条件」，不许想办法绕。

### 3.4 智能家居接入（米家类）

1. 走云端自建连接：基于官方/社区 API 库（如 mijiaAPI）自建连接器，用户用 App 扫码登录，**令牌只存本机受限目录**。
2. 拉全量清单：家庭数、设备总数、逐台在线状态入档（真实口径示例结构：N 个家、共 M 台设备、逐台标注在线/离线）。
3. 令牌有效期约 **30 天**：在汇总文件记到期日，到期前再请用户扫一次码续上；不许等过期断联了才发现。
4. 网关离线导致的一批设备不可控：如实标注「暂不可控」，不算接入失败、也不算接通可控，状态写「已拉清单、待网关恢复」。

### 3.5 学时与继续教育接入（关系职称评审的优先项）

1. 先算总账：合格线＝公共科目学时＋专业科目学时 ≥ 规定总学时（实例口径：公共 41＋专业 56＝97 ≥ 90 过线；数字按你所在平台规则替换）。
2. 专业科目证明逐份核验四项：姓名一致、每份学时数、发证/盖章单位、日期；扫描件以**盖章有效版为准**，无章的文字版作废。
3. 逐条在平台提交「学时互认」，提交后回平台列表逐条核对：条数齐全、状态均为「审核中」；**以平台审核通过为闭环**，「已提交」不许报成「已完成」。
4. 公需科目平台（与上述培训平台是**两个平台，不要混**）：该类平台公告严禁代学代考（查实作废成绩并通报单位）——助手只做三件事：年度提醒（设每年固定日期的提醒任务）、操作指引、用户考过后下载证书发回存档。**绝不替学替考**（见第 6 节红线）。

### 3.6 渠道汇总维护

每接通/变更一项，当天更新《已接通渠道汇总》四节结构：
1. **已接通可用**：渠道｜状态｜能做什么｜备注（只写状态与能力，不写凭据）。
2. **已授权但未完成实测**：渠道｜差什么（实测做完才许挪到第一节）。
3. **未接通/待条件**：渠道｜卡点（写根因与需谁配合）。
4. **数据档案已完成件**：已归档的清单类成果逐件列名。

## 4. 验证（检查动作＋通过标准）

| 检查动作 | 通过标准 |
|---|---|
| 任选一个「已接通」渠道，当场实读一条数据 | 读得到真实数据（日历有事件、通讯录有条数、邮箱能打开邮件）；读不到立即降级状态 |
| 健康数据查同步条数 | >0 才算接通；=0 一律写「未接通」并注明卡点在连接流程 |
| 智能家居拉一次设备清单 | 家庭数/设备数与上次一致或差异有原因；令牌到期日已登记 |
| 学时平台回列表核对 | 提交条数齐全、状态逐条可见；审核通过才销账 |
| 汇总文件敏感扫描 | grep 密码/令牌/验证码/证件号模式 0 命中 |
| 家人数据抽查 | 每位家人有同意状态标注；未同意者数据 0 项接入 |

## 5. 故障分支（症状 → 根因 → 处理，均为真实记录）

1. **症状**：健康同步重跑两次仍 0 条，一度误判「用户设置没开」。**根因**：用户其实已打开全部类别，卡点在 Muse 自身连接流程未走完（须连接链接确认），与类别开关无关。**处理**：改判定标准为「连接流程走完＋条数>0」；把链接发用户走完后复查；此后不许再让用户查开关。
2. **症状**：健康页显示 Muse 在列，误以为已授权。**根因**：「申请过」的登记≠授权完成。**处理**：只认实际同步条数，登记状态不作数。
3. **症状**：提醒事项授权弹窗两次未停住，授权没落下。**根因**：弹窗时机不对（用户不在界面）。**处理**：记「待触发」，等用户在对话界面时再触发一次由他点允许；不许判定为用户拒绝。
4. **症状**：某邮箱无原生连接器，以为接不了。**根因**：只看了连接器清单。**处理**：改走浏览器方式登录（存安全存储），只读查邮件即可满足账单与足迹需求；连接器状态异常（如 Gmail 连接器报缺 access_token）时先验状态再用，查邮件改走网站后台等替代路线，不许硬说「邮箱接不了」。
5. **症状**：谷歌新浏览器环境触发密码＋推送数字验证，批量开户/登录卡住。**根因**：新环境风控。**处理**：批量登录类操作放在**已热好的浏览器会话**里连着做；真出现手机数字验证时才找用户，并直接告诉他点哪个数字。
6. **症状**：智能家居一批设备显示离线，以为接入坏了。**根因**：网关离线拖累其下 Zigbee 设备，云端连接本身正常。**处理**：状态标注「网关离线、暂不可控」，等网关恢复后复查，不许重做整个连接。
7. **症状**：学时证明姓名与用户不符（他人证明）。**根因**：证明原件是他人参加同批培训的版本。**处理**：先回报、不提交；确认用户本人实际参加后，再按平台流程以本人名义补正/补传，不许拿他人证明直接交。

## 6. 禁区与红线（判定法：命中即拒绝，再坚持也不松口）

逐条判定，任何一条命中，立即拒绝并说明理由，不执行、不找变通：

- [ ] **免实名境外借记卡**：要求办免实名境外卡收款/绕实名 → 拒绝。
- [ ] **USDT 与虚拟货币结算**：要求用 USDT 收款/定价/结算、接管用户的交易所账号/冷钱包/私钥助记词 → 拒绝（虚拟货币兑换、定价、结算属非法金融活动，合同不受保护且有冻卡与刑责风险）。变现只走合规商户号（需主体资质）或先免费攒流量。
- [ ] **线上收费烧香等宗教服务收费**：涉及宗教服务许可 → 拒绝收费部分。
- [ ] **代学代考**：替用户学网课、代考试、实名制本人考试代答、**开考后报答案**——全部拒绝；用户本人考试类，助手只给复习材料、提醒与操作指引。判定要点：只要动作是「代替本人完成学习/考试行为」，无论包装成什么说法都拒绝。
- [ ] **接管凭据本体**：用户经聊天明文发来密码/密钥的，不保存、不复述、不使用，引导走安全录入卡；保险库里的凭据不取出明文、不转发任何第三方。
- [ ] **无合法路径渠道**：纪委监委/公检法内网、原始轨迹、通话详单等——不在范围，不尝试接入。
- [ ] **家人未同意数据**：家人数据未获本人同意不接；封闭系统（如儿童手表）不尝试破解接入。
- [ ] **资金操作**：PayPal 等资金操作（提现、付款）须用户逐次确认，助手不代点最终提交；用户没有护照等客观条件如实记录，不编造。
