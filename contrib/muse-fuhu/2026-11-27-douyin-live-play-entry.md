## 〇、结论先行

1. **路线走得通**：个人主体可入驻、可提案、可上线，官方流程完整闭环（入驻→创建玩法→提案→能力→开发→提审→内测→全量）。
2. **关键路径是软著**：平台侧环节合计约 2–3 周即可走完；软著自办受理后 30–60 个工作日、全程 2–3 个月，是整条线唯一以月计的前置。必须第一天就启动，且**先定名、再申请**（下文顺序不可颠倒）。
3. **最大卡点（我方特有，比周期更硬）**：2026-03-15 起软著新版申请表要求签章页**手抄承诺「未使用 AI 开发编写代码、撰写文档或生成登记申请材料」**，并转入实质审查（代码相似度、功能—代码—文档一致性核查、失信惩戒）。我方玩法代码若由 AI 研发端生成，该承诺正面冲突——这不是流程问题，是路线 A 的单点合规风险，须在立项时先行处置（见 §7 卡点 1），不许虚假承诺过关。
4. **次级卡点**：玩法最终产物须为可运行 **exe**（官方教程与 SDK 以 Windows＋Unity 为主线），与我方「直播固定在 Mac」的定版存在运行环境冲突，Mac 口径未确认（见 §7 卡点 2）；虚拟主播＋玩法无明文放行，提案逐案评估（见 §7 卡点 3）。
5. 拿到的是**玩法事件**（关键词命中的评论、点赞、礼物、粉丝团），不是全量自由弹幕流——边界复核见 §5，与专题4结论一致。

## 一、入驻主体要求（个人主体）

入口：抖音开放平台 developer.open-douyin.com → 注册账号 → 账号中心 → 身份&角色 → 资质认证 → 选「个人身份」。

- [] 注册方式：未注册过的手机号/邮箱注册，或抖音号扫码授权登录（二选一）。
- [] 主体资格：年满 18 周岁；仅支持中华人民共和国居民身份证（暂不支持其他个人证件类型）；不得冒用他人证件。
- [] 提交材料（个人身份）：
- 身份证正反面照片（清晰、边角完整，jpg/png/jpeg，≤5M）；
- 个人姓名、证件号码（字母大写）、证件有效期、地区——四项须与身份证完全一致；
- 实名核验二选一：与主体同名的实名手机号，或与主体同名的实名银行账户。
- [] 审核时效：个人身份约 **1 个工作日**（企业约 3 个工作日）。
- [] 个人主体可创建的应用类型含**小玩法**/小游戏/小程序（官方入驻页明文）。
- [] **不可逆提示**：个人主体一经认证，不支持变更证件号码与主体类型，不支持个人转企业。主体选错只能换号重来。
- [] 类目：直播小玩法不走小程序式「主营类目＋备案」流程；准入靠提案评估（§2）＋平台准入规则（非明确禁止的内容均可提案）。无单独类目申请动作。
- [] 费用：官方文档未提及入驻收费（未确认，推定免费）。

**主体一致性铁律（贯穿全程）**：入驻主体 ＝ 软著著作权人 ＝ 运营主体 ＝ 结算主体，四者必须同一人/同一主体；软著「不支持转授权」绕不过去。所以软著必须以入驻的那个个人名义申请，不能借他人软著。

## 二、创建玩法与提案流程

### 2.1 创建玩法（即时）

- [] 控制台 → 直播玩法 → 创建小玩法 → 类型选****（选错类型后续基础设置会显示非弹幕小玩法，须重建）。
- [] 创建完成即得 **AppID**（玩法唯一标识，SDK 初始化要用）。
- [] **名称在此定版**：每款玩法仅 **1 次改名机会**，且改名后仍须与软著名称一致。先定名再动软著（§3）。

### 2.2 提案评估（约 2 个工作日）

- [] 提案前必读《直播玩法规范自查 checklist》（官方创建文档内链；本次公开抓取未取得全文，内容**未确认**，正式执行时在后台内打开逐项自查）。
- [] 提案载体：后台「提案管理」入口提交**飞书文档**（注意：飞书自动生成的 wiki 格式传不上，须手动转 docx；文档打开对外阅读＋副本创建权限；建议用 Chrome 提交）。
- [] 提案文档必备要素（官方模板口径）：
- 角色与画面（用**正式美术资源**，不是占位图）；
- 主播做什么、观众怎么参与；
- 弹幕指令与礼物分别对应什么效果；
- 一局如何开始、如何结束；
- 效果如何叠加、如何收尾；规则、排名与积分清除逻辑。
- [] **Demo 视频必须提供**（无模板）：展示正式美术＋完整基本玩法逻辑即可，无需穷尽全部角色；尚无 API 时可用本地模拟指令效果录制。
- [] 评估维度：美术品质、玩法设计、题材选型；主要拦截「质量明显不达标」与规范性问题。评估每天进行，**工作日次日反馈**；创建文档口径为审核周期约 2 个工作日。
- [] 通过率与背景无关：官方明文评审只看提案质量，与提交者背景无关；不通过可按意见修改后继续提交。
- [] 通过后：按后台指示加入技术对接群，再进入能力申请（§2.3）。
- [] **版权前置（提案阶段就查）**：提案初评时涉及版权内容使用，须已提供授权文件与资质文件；无授权书直接不过——不许「先提案、后补授权」，更不许提案用无版权美术、上线再换（官方明文禁止）。

### 2.3 能力申请（提案通过后，后台点击自动开通）

必选四项＋免申请一项：

- [] 获取礼物互动数据（必选）
- [] 获取点赞互动数据（必选）
- [] 直播间评论互动数据（必选）
- [] 玩法客户端（exe）（必选，原「包体管理能力」）
- [] 获取直播信息（无需申请）
- [] 获取粉丝团数据（可选）
- [] 弹幕云启动（可选；走抖音云可免域名备案、走内网专线推送）
- [] 官方题库（仅答题类必选，且须先联系对接运营审批）

### 2.4 开发配置与指令设置

- [] 开发配置模块：选定数据通路三选一——①LiveOpenSDK 指令直推（玩法 exe 内集成，可不搭服务器）；②HTTP 回调＋自有后端（需域名、备案、HTTPS）；③抖音云（免备案，官方称首次接入 3–14 人天）。
- [] 营收 → 礼物评论配置：添加礼物（从平台礼物池选，见 §5）并记录礼物 ID；新增评论关键词（上限见 §5）。
- [] 履约上报须接入：效果实际展示完成后调用官方履约（Ack）接口，只「收到」不算完成。

### 2.5 基础设置与资质提审

- [] 基础信息：玩法名称、简述（10–20 字）、图标、简介（20–150 字）、横向封面、纵向介绍图、介绍视频、**开播文档**（主播最重要的上手说明，须详细严谨）、玩法规则（规则介绍、评论/点赞效果、礼物效果）、小魔盒配置（观众侧参与说明）。
- [] 资质信息：在基础设置内提交软著与授权链文件（§3、§4）。
- [] 顺序约束：**基础信息提审与版本提审不能同时进行**，自行排好先后。
- [] 版本提审：每次提审包体版本号必须递增；平台**不支持版本回滚**；无合规问题时版本审核约 **4 个工作日**。
- [] 官方总时标（成品口径）：提案评估约 2 个工作日＋上线审核约 4 个工作日，其余耗时取决于开发者接入与驳回重审。
