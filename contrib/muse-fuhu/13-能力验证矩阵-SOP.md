# 13 能力验证矩阵与状态口径

- 目的：把「能不能干」从印象变成逐行留证的矩阵。每行一项能力，列固定为：能力域 / 尝试次数 / 原始证据路径 / 状态 / 阻塞原文 / 下轮攻坚路线。
- 状态只用五档：通过｜阻塞｜未测｜待人工｜换路通过。未测≠通过；单次成功不算通过；降级完成、静默丢弃一律不算通过。
- 「通过」的门槛是三重放：①换入口重放（不同入口各跑一次，如 App 与微信桥）；②换参数重放（换文件、换账号、换时间窗）；③造一次故障并恢复留证（杀进程、断网、撤权限后按恢复路径走通）。三者缺一，不许记通过。
- 证据只认原始输出：终端 stdout、HTTP 响应与 ret 码、审批卡原文、页面原文、对方实收、文件路径。转述与印象不算证据。
- 需外部凭证、外部输入、界面点选或身份校验的步骤记「待人工」，随心跳汇总，不阻塞主流程，并行推进替代路径。
- 跑不通走攻坚升级链：复现 → 贴原始报错 → 查官方文档 → 全网全量搜（中英双语加视频平台）→ 换实现 → 仍不通写入阻塞表并附全部证据。
- 红线类能力（如重置、删除账号）记「禁测」，不列入攻坚。
- 维护：每轮攻坚后回填对应行；同一能力在多处出现时以证据最新的一行为准，其余行注明同源，避免口径打架。
- 实测参考（2026-11-26 首建）：全表 121 行——通过 0、换路通过 1、阻塞 7、待人工 7、未测 106。严判之下通过为零是常态，不是失败。
