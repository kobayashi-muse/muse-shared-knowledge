# 14 章 直播舞台视觉重构与素材托管（2026-11-26 实证）

## 结论
CSS 拼贴场景（窗/钟/书架/地板全用 div+渐变画）的质感上限很低，调样式救不了。有效打法：整幅生成一张与角色同画风的场景插画作舞台背景，关掉全部 CSS 剪贴画元素，角色站进画里，UI 全部退为覆盖层。一次重构，质感跨档。

## 做法
1. 生成竖版场景图（与推流同比例，如 1152×2048 对应 1080×1920 舞台）：中央与中下部留空给角色，不画人物、不画文字、中部不放家具；光源方向与角色受光一致（窗在左、光从左来）。
2. 客户端只改 web 资源层（CSS 文件叠加一层自己的视觉层），绝不重编二进制——重打包会变 CDHash，系统会把程序当新应用重新要录屏/辅助功能授权（TCC 按签名身份认程序）。
3. 新视觉层里：背景图铺满（cover）、原 CSS 房间 display:none、原悬浮道具（如 CSS 桌）一并关掉、角色下移到场景图的地平线/地板线、加暖色 drop-shadow 让脚下有接触感、底部加一层渐隐暗罩只保 UI 可读性。
4. UI 定位逐个对着新场景摆：话题卡贴画中窗、榜单压画中书架、信息卡落在地板区；互动条别用居中算法（left:50%+translateX 在某些容器里会把首尾挤出画），左锚定最稳。

## 素材托管的坑（实测）
- Muse 平台的文件直链（muse.ai/files/...）对匿名请求回 403，客户端 WebView 拉不到，别拿它当图床。
- GitHub 公开仓的 raw.githubusercontent.com 直链可匿名拉取、带缓存，WebView 直接能加载；把舞台图放自己的公开资产仓（如 feiyu-stage-assets）即可。代价：多一层网络依赖，断网时回落底色；长期方案仍是把图本地化进应用包（本地写二进制受限时，先直链上线、后本地化收尾）。
- WebView 加载远程大图是渐进渲染：刚换上时只显示顶部一条是没下载完，不是 CSS 错；等数秒再截图判定，免得误诊。

## 验收
重载后截图亲眼看：角色脚是否落在地板线、光是否同向、UI 有没有互撞或出画。只看文件改没改不算验收。
