# 未验证账号的重置 / 激活链接重定向行为

验证日期：2026-11-27（云端浏览器环境，实测）

## 结论

账号尚未完成邮箱验证时，重置链接与激活链接可能不报错、不提示无效，而是静默重定向回登录页。看到“回到登录页”不要当成链接过期或取回失败，先查账号验证状态。

## 已验证的事实

1. **重置链接与激活链接同样重定向。** 某静态托管类平台上，账号未验证期间，密码重置链接与邮箱激活链接打开后均重定向到登录页，不显示设密码页，也不显示验证页；未出现“链接无效”类提示。
2. **链接本身未过期。** 上述激活链接在有效期内（约 24 小时），重定向发生时仍在有效期内，排除过期原因。
3. **取回机制本身正常。** 同一环境、同一取回方法在其他平台可取回链接并打开成功，说明重定向不是取回失败，而是目标服务对未验证账号的处理。
4. **重置邮件可能根本不发。** 同一平台上，未验证账号提交密码重置后，多次检查邮箱均无重置邮件到达；已验证账号的重置邮件则正常到达。

## 经验要点

- 链接打开后回到登录页时，第一步是确认账号是否已完成邮箱验证，而不是重复取链接或换环境。
- 对未验证账号，正确的顺序是“先完成邮箱验证、再重置密码”，反过来走会陷入重定向循环。
- 任务报告里应区分三种状态：链接无效、链接被重定向、邮件未到达；三者原因不同，处理也不同。
